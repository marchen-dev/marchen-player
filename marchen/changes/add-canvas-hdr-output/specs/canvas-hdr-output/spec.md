## 目的

在支持的桌面环境呈现 HDR 视频的高光范围和正确色彩，在能力不足时维持正确 SDR 播放及可信状态。

### 需求: 正确识别和呈现 HDR

系统 MUST 根据传递函数及色彩信息识别 HDR，本次 HDR 输出支持范围为原本已走 HEVC 软件解码的 HDR10/PQ 和 HLG；SHALL 保留解码至输出所需的位深和高光信息，不得先压缩为 SDR 再标记 HDR。

#### 场景: PQ 或 HLG 视频在支持环境播放

- **GIVEN** 视频因既有解码能力选择而使用 HEVC 软件解码，色彩信息完整，当前桌面环境和显示器支持已验证的 HDR 输出
- **WHEN** 用户使用 Canvas 播放 PQ 或 HLG 视频
- **THEN** 高光超过参考 SDR 白的内容在显示能力内保持可区分，灰阶、肤色和色域转换正确
- **AND** 软件解码的 10bit 精度保留至高精度输出，黑边保持黑色，旋转和裁剪正确

#### 场景: 输出设备支持 HDR 但帧导入未保留高光

- **GIVEN** HDR 输出设备和画布能力可用，但已知参考图的亮度关系未通过端到端验证
- **WHEN** 系统决定视频输出路径和展示状态
- **THEN** 不得仅凭设备能力标记已输出 HDR，使用正确的 SDR 回退
- **AND** 不得通过任意整体提亮掩盖高光压缩，不把尚未排除的测试解释错误断言为浏览器缺陷

#### 场景: 10bit SDR 视频

- **GIVEN** 视频为 10bit 但传递函数为 SDR
- **WHEN** 开始播放
- **THEN** 系统沿用 SDR 输出，不因位深启用 HDR

### 需求: 硬解优先与限定交付范围

系统 MUST 保持已有解码后端选择，Canvas 的 WebCodecs 路径在本次维持 HDR→SDR；不得因 HDR 输出诉求自动强制软解。H5 SHALL 继续浏览器原生播放，本次不新增视频输送或呈现链路。

#### 场景: HDR 屏幕上使用 WebCodecs

- **GIVEN** 当前视频被既有策略选择为 WebCodecs 解码，显示器支持 HDR
- **WHEN** 开始 Canvas 播放
- **THEN** 保持该后端和现有 SDR 输出，设置显示 HDR→SDR
- **AND** 原因说明为当前解码路径暂不支持 HDR 输出，而非显示器不支持 HDR
- **AND** 不提供强制软解 HDR 开关，不加载本次新增的软解 HDR 资源

### 需求: 能力不足时正确回退

系统 MUST 在 HDR 输出不可用、输出失效或颜色信息无法可靠解释时给出明确状态；输出失败不得强制从可用硬解切换至软件解码。可正确转 SDR 时 SHALL 继续播放，否则 SHALL 使用统一无法播放页面，不能输出猜测的颜色。

#### 场景: SDR 显示器或无 HDR 渲染能力

- **GIVEN** 当前环境支持 Canvas，但不具备可用 HDR 输出
- **WHEN** 打开 HDR 视频
- **THEN** 视频使用现有正确的 HDR→SDR 输出，解码后端不因呈现限制改变
- **AND** 设置显示 HDR→SDR 及简短回退原因

#### 场景: 已禁用 Canvas 的浏览器

- **GIVEN** 用户使用当前不支持 Canvas 的 Safari 或 Firefox
- **WHEN** 播放或打开内核设置
- **THEN** 原 Canvas 禁用与禁止降级规则不变，不因新增 HDR 放开入口

### 需求: 输出状态与用户界面可信

系统 SHALL 区分来源 HDR、输出 HDR、HDR→SDR 和原生浏览器管理状态。只有路径成功呈现且满足已验证条件时才标记 HDR；不得把 API 存在或屏幕检测阳性当作已输出。字幕弹幕 MUST 保持可读，预览及历史封面 SHALL 继续 SDR。

#### 场景: 初始化与回退状态

- **GIVEN** HDR 输出正在初始化，或初始化失败
- **WHEN** 用户查看播放信息
- **THEN** 不提前显示已输出 HDR；成功或回退后更新真实状态
- **AND** H5 未获得实际 HDR 呈现证据时仅标记浏览器原生管理

#### 场景: 覆盖层和预览

- **GIVEN** HDR 视频正在播放且启用字幕和弹幕
- **WHEN** 用户观看并悬停进度条
- **THEN** 覆盖层布局、时间同步和可读性正常，预览为可辨认的 SDR 图像
