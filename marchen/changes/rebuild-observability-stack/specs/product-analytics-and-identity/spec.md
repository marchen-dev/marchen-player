## 目的

通过统一的匿名身份和产品事件体系衡量活跃安装、留存、页面访问、功能使用与漏斗，并让 Electron 与 Web 数据可以分端分析或合并观察。

### 需求: 稳定匿名安装身份

系统 SHALL 为没有账号体系的用户生成随机、稳定且可重置的匿名安装标识，并 SHALL 在错误监控与产品分析中使用相同标识。

#### 场景: Electron 多次启动

- **GIVEN** 用户未重置应用数据
- **WHEN** 用户多次启动同一 Electron 安装
- **THEN** 各次会话使用相同匿名安装标识
- **AND** 每次启动具有不同的应用会话标识

#### 场景: 用户重置应用

- **GIVEN** 用户执行应用数据重置
- **WHEN** 重置完成并重新启动应用
- **THEN** 旧产品分析身份和待发送队列被清除
- **AND** 新会话生成新的匿名安装标识
- **AND** 错误监控不再沿用旧用户身份

### 需求: 统一事件公共属性

所有产品事件 SHALL 包含可用于分组的目标端、版本、release、平台、架构、应用会话和环境；与播放相关的事件 SHALL 额外包含播放会话标识。

#### 场景: 同时分析 Electron 与 Web

- **GIVEN** Electron 与 Web 使用同一产品分析项目
- **WHEN** 分析页面访问或功能使用事件
- **THEN** 可通过 `app_target` 分别查看 Electron 与 Web
- **AND** 也可在不拆分项目的情况下计算整体趋势

### 需求: 页面和功能使用可被明确衡量

系统 SHALL 使用稳定路由名记录页面访问，并 SHALL 对字幕、弹幕、倍速、全屏、匹配、设置和影视库等核心功能发送类型稳定的显式事件。

#### 场景: Electron Hash 路由切换

- **GIVEN** Electron 页面地址基于本地文件和 HashRouter
- **WHEN** 用户从播放器进入影视库
- **THEN** 产品分析记录稳定的 `/library` 页面名
- **AND** 事件不以安装目录或完整 `file://` 地址作为页面名

#### 场景: 用户切换字幕

- **GIVEN** 播放会话处于活动状态
- **WHEN** 用户启用、关闭或切换字幕
- **THEN** 系统记录一次对应功能事件
- **AND** 事件可关联到当前播放会话但不依赖 UI 组件名称

### 需求: 支持活跃、留存与核心漏斗

系统 SHALL 提供计算活跃安装数、次日/七日/三十日留存和“启动→打开视频→匹配完成→开始播放”的漏斗所需事件。

#### 场景: 完成一次正常播放启动

- **GIVEN** 用户启动应用并打开本地视频
- **WHEN** 视频成功开始播放
- **THEN** 产品分析中存在应用会话开始、视频导入完成、匹配完成和播放开始事件
- **AND** 这些事件可按同一匿名安装与应用会话组成漏斗

### 需求: 常规会话回放

系统 SHALL 允许产品分析平台采集普通会话回放，并 SHALL 使用采样或远端触发控制成本；错误回放的权威链接仍由错误监控平台承担。

#### 场景: 普通产品会话被采样

- **GIVEN** 当前会话命中产品回放采样或触发规则
- **WHEN** 用户浏览页面并使用播放器控制
- **THEN** 产品分析平台可回放该操作路径
- **AND** 高频媒体、弹幕和字幕层遵守与错误回放相同的性能隔离规则

### 需求: 产品分析不重复错误追踪

系统 MUST NOT 同时把 PostHog Error Tracking 作为生产错误的第二权威来源；错误应由 Sentry 管理，产品事件只携带可用于漏斗分析的结果码与关联信息。

#### 场景: 播放失败

- **GIVEN** 一次播放失败已提交到错误监控平台
- **WHEN** 产品分析记录播放结果
- **THEN** 只发送 `playback_failed` 及稳定错误码等产品属性
- **AND** 不在产品分析平台重复创建异常问题

### 需求: Feature Flag 不得控制关键正确性

Feature Flag MAY 控制非关键 UI、实验和渐进展示，但 MUST NOT 决定数据库迁移、文件安全、FFmpeg 资源治理或播放正确性。

#### 场景: Feature Flag 服务不可用

- **GIVEN** 应用离线或远端 Flag 服务超时
- **WHEN** 应用启动并播放视频
- **THEN** 应用使用本地默认值或缓存值继续工作
- **AND** 核心播放和数据迁移不被阻塞

### 需求: 离线关键事件可恢复

系统 SHOULD 为关键产品事件提供有界离线队列和幂等标识，在网络恢复后补发且不得无限占用本地存储。

#### 场景: 离线完成一次播放

- **GIVEN** 应用播放期间无法连接产品分析服务
- **WHEN** 播放会话结束后网络恢复
- **THEN** 尚未过期的关键事件可补发
- **AND** 同一事件不会因重试被计算多次
- **AND** Session Replay 数据不进入自建离线队列
