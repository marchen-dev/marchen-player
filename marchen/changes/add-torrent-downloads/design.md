## 背景

本提案承接当前讨论，未引入或晋升已有 Idea。参考用户提供的 Marchen 影视库截图和现有侧栏/设置/弹窗组件。Product Design 的 user-context 预检未发现保存配置；视觉依据是当前产品，不另建网站或替换设计系统。

当前 Renderer 用 Dexie v1 的 history/library；主进程已有同步 lowdb 通用存储。文件打开入口提前接收系统事件，但仅接受视频且只保留最新意图。ElectronImporter.importFromPath 会扫描同目录视频并计算媒体 hash。下载模块须衔接这些入口，不迁移播放数据库，也不复用单槽视频请求保存多个种子。

## 目标与非目标

**目标：** Electron 内完成添加、选集、下载、恢复、完成即停止与本地播放闭环；任务独立于页面存活；下载与观看身份分离；可验证双平台文件关联。

**非目标：** 边下边播、浏览器 BT、系统磁力关联、后台守护进程、资源搜索/RSS/自动追番、下载后自动入库、修改解码内核、原生 libtorrent 封装。

## 决策

### 1. 引擎与验证门禁

以 Node 端 WebTorrent 为首选，用 DownloadEngine Port 隔离库 API。依赖在实施时验证后锁精确版本；BT v1 为首版最低门禁，v2/混合种子分别测试并形成支持矩阵，未通过则在输入时明确拒绝，不静默回退、不宣称通用支持。如果 v1、真实停止或可靠恢复无法通过，暂停后续实现并修订选型，不绕过门禁。

开发门槛只包含本机引擎、开发态 utilityProcess 和输入/统计规则验证。macOS ARM64、Windows x64 的安装包依赖加载、asar、文件读写、停止和文件关联，在交付阶段分别验收；缺少 Windows 环境不阻塞本机开发，但必须保留该平台未验收状态，不得将本机通过等同双平台交付完成。

先用自有可控样片种子与本地 peer 验证下载字节、hash、选集及故障恢复，再用公开可再分发资源辅助验证公网发现。不得只用一次公网下载作性能或平台结论。

官方接口依据：https://webtorrent.io/docs 。pause() 仅停止主动建立新连接，不能实现用户期望的停止。优先验证关闭单个 torrent 的全部连接且不销毁 store，再从持久元数据和原目录重建的方案。停止状态必须等引擎确认 socket/store 已关闭；期间显示「正在暂停」。恢复不使用无条件 skipVerify。

### 2. 进程与状态所有权

Renderer → 类型化 downloads IPC → Main DownloadService / DownloadRepository → utilityProcess 内 WebTorrent。

Main 是任务唯一写入者，下载进程报告事实，Renderer 仅订阅 DTO。异步命令带 requestId，快照/事件带 revision 和进程 generation，忽略旧进程消息；界面订阅后拉取快照并按 revision 合并，重挂载不重复注册下载。

IPC 覆盖 prepare/confirm/cancelDraft/list/pause/resume/retry/remove/openFolder/play/getSettings/setSettings。校验调用窗口、枚举、路径与任务所有权，禁止 Renderer 直接销毁任意路径。速度与进度推送最多约 2 次/秒，关键状态立即发送。utilityProcess 产物单独构建；开发阶段验证本机依赖加载与进程通信，交付阶段确认两个目标平台安装包中的 asar 资源、Node/原生依赖、文件读写与停止行为。

期望状态 running/paused/stopped 与实际状态 resolving/checking/waiting/downloading/pausing/paused/completed/error 分开。进程崩溃令运行任务进入可重试错误，不能让播放主进程退出或无限自动重启。

### 3. 持久化

在隔离后的 app userData 下建立 downloads/tasks.json、downloads/metadata/<taskId>.torrent；视频直接按种子原有文件或文件夹名写入用户选定目录，不再创建 Marchen 外层目录。采用异步 JSON 仓库、串行写入队列、同目录临时文件替换、上一版备份、schemaVersion、启动校验与明确迁移。不得直接用现有同步 store 高频写入；不得把视频、磁力中的敏感 tracker 参数或完整路径写入遥测。

任务记录：taskId、规范化 infoHash/资源标识、显示名、元数据引用、目标根目录、文件索引/相对路径/大小、selectedFileIndices、desiredState、createdAt/updatedAt、lastError、completedAt、累计 uploadedBytes、下载基准及 completedSeedingMs、policy 快照。磁力在元数据未取得前持久保存用于恢复；元数据落盘后仍保留必要 tracker 配置但不外发。

速度、peer 数和 ETA 只在内存。状态变更和退出及时 flush，统计默认每 5 秒 checkpoint；崩溃最多损失一个 checkpoint 的统计，不伪称精确计费。未知版本或损坏主文件尝试有效备份，保留故障文件并提示，不能自动清空记录或删除视频。

恢复扫描已有文件，文件移动/缺失或 hash 失败撤销 ready 状态。用户暂停任务不能在恢复时自动联网；停止任务的磁盘核对也不可变成隐式继续下载。备份恢复后允许保守重新校验，不信任陈旧 bitfield。

### 4. 添加、选集与完成判定

磁力 prepare 阶段仅获取元数据；torrent 默认取消有效载荷选择，用户确认后才选择 pieces。草稿关闭销毁临时网络对象。输入大小、文件数、路径深度和元数据等待设集中预算，超限给出可读错误；首版预算：200 个任务、8 个草稿、8 MiB 种子元数据、16 KiB 磁力、10000 文件、32 层路径；元数据等待 60 秒、停止 15 秒、校验启动最多 10 分钟。种子分块支持 16 KiB–16 MiB。

相同资源用 infoHash 去重，多个未知磁力先按规范化标识去重。下载文件保留原目录关系，创建任务时独占预留顶层文件或目录名称，遇到已有同名内容拒绝开始并提示更换保存目录。旧任务继续使用原路径，不自动搬迁。校验相对路径、绝对路径、..、盘符、符号链接逃逸及 Windows 文件名规则；冲突必须提示或拒绝，不能悄悄改名破坏字幕关系。

默认勾选支持的视频及字幕/字体附件，其余文件可手动选择，开始前展示精确选中清单。跨文件 piece 可能携带邻接文件字节，按引擎存储事实记录占用并验证不会误报那些文件完整。任务完成按 selected files 校验结果，而非整个 torrent.done；逐文件的可播放状态独立。

### 5. 完成停止、退出与清除

所有已选文件完成校验后，停止任务传输并关闭文件句柄，成功后显示已完成。完成任务不能恢复传输；下载期间仍参与 BT 分片交换。上传限速默认不限速，正整数表示字节/秒，不接受 0，修改后立即应用。

选中文件逻辑大小持久化为 selectedBytes。读取旧版记录时兼容 ratioBaseBytes，丢弃策略、累计上传和做种时长；恢复时先离线校验，完整任务设置 stopped，不再连接网络。未完成且运行意图为 running 的任务继续恢复下载。

macOS 关闭最后窗口保持现有应用存活及下载；真正 Quit 有活动任务时提供退出/取消，退出会停止进程并 flush。Windows 关闭最后窗口走同一退出保护，无隐藏后台常驻。清除应用数据先取得清理锁、停止所有任务并等待文件句柄关闭，再清任务/元数据和下载设置；下载目录不随 app 数据清除，失败必须报告。

### 6. 播放联动与删除

play(taskId,fileIndex) 在 Main 重新核对完成、文件存在和归属，给既有导入流程真实路径。torrent infoHash 只标识下载，视频前缀 MD5 仍承担现有历史/匹配身份，不新增 torrent 类型到 HISTORY。

下载完成不触发 loadFromPath 或 library 写入。首次播放创建既有历史，作品匹配成功后按既有规则关联 library；未识别文件不承诺自动入库。合集中未播放的文件不批量建立观看关联。

Main 提供受管理文件可用性查询，挂到同目录列表生成及受管理路径打开校验，覆盖下载页、系统视频打开和历史恢复，避免从其他入口读到未完成文件。字幕发现应排除受管理的未完成附件，已完成文件继续使用既有字幕命名和字体规则。

删除任务默认保留文件；显式删除文件仅操作清单内归属已核对的文件，不递归清空用户目录。结合当前媒体租约/播放会话判断占用，包括暂停播放；停止传输后才删除。共享任务或正在播放占用时拒绝物理删除。历史不批量清空，失效来源沿用已有错误处理。

### 7. 系统文件打开

electron-builder 分别新增 torrent 关联；不修改默认应用，不新增 magnet 系统协议。将打开请求扩展为 video/torrent discriminated union：视频保留最新播放意图，种子用有界 FIFO 队列并按内容去重。argv 解析支持多个绝对文件路径，不能只取最后参数，也不能把开关当种子。

监听保持在异步初始化前，等待 Renderer 就绪后依次进入新建弹窗；取消当前项继续下一个。主窗口已销毁则重建、最小化则恢复。视频导入和种子弹窗不得相互覆盖或重复消费。安装包实测冷启动、热启动、关闭窗口、启动中多文件、无效文件和重复种子。

### 8. UI 与交互设计

沿用用户截图：左侧图标导航，下载排在影视库后、设置仍在底部；MingCute 下载图标、灰色圆角选中底、右侧 Tooltip；仅 Electron 路由。页面不使用影视库大封面 hero，不依赖动漫联网识别。

页面结构：标题「下载」/右侧「新建下载」；下一行全部/进行中/已完成与名称搜索；紧凑行列表，每行主名称、细进度条、已下载/总大小、速度及 ETA，右侧适用主操作和更多菜单。行展开合集文件清单，完成的单集独立播放。已完成筛选包含选中文件均已完成的任务；进行中包括未完成暂停/错误；解析草稿显示在弹窗而非伪造正式任务。

新建弹窗第一步粘贴磁力或选种子，第二步文件勾选、总大小和目录；解析中可取消，有超时重试；不自动读取剪贴板。种子拖入只在下载页及明确接收区处理，不改变播放器的视频拖入行为。

状态文案：正在获取文件信息/正在校验/等待连接/下载中/正在暂停/已暂停/已完成/下载失败。空列表提供添加入口，无搜索结果提供清空筛选；未知 ETA 显示估算中。错误留在任务行，完成只 toast 不抢焦点。目录缺失或空间不足有明确重试动作。

下载设置置于应用通用设置的「下载」分组，提供默认目录和下载期间的上传限速；任务更多菜单包含打开目录与移除。删除弹窗默认不勾选同时删除文件。

沿用 shadcn/ModalStack/现有 toast、主题色和箭头指针；主要 CTA 和下载进度用现有红色强调，错误不只靠颜色。检查 800×650 最小桌面尺寸、常用 1400×900、明暗主题、键盘焦点与长中文/英文文件名；不新增移动端适配。正式界面实现后用真实截图验收，当前文档不是已验收视觉稿。

## 风险与权衡

- WebTorrent 速度受 peer 和网络影响，不能承诺跑满带宽；暂停重建可能触发耗时校验，必须呈现真实状态。
- 格式矩阵及本机 Node 24/Electron 44 开发态依赖属于开发门禁；双平台 utilityProcess 打包属于交付验收。失败需按对应阶段处理，不以库文档或交叉构建替代目标平台运行实证。
- JSON 适合首版有限任务数，不适合高频全量写入；采用节流、串行和备份，未来可在 Repository 内迁移 SQLite。
- 用户截图是视觉参考，尚无下载页实机验收；所有 UI 和平台支持结论以 change evidence 为准。
- 已有引擎验证脚本和本机实验，详见 evidence/engine-verification.md；业务/UI 尚未实现。任务清单中的验证项必须实际完成后才能勾选，旧证据中的暂停理由仅代表调整前状态。


### 下载中修改选集

任务标题悬停变色，点击展开或收起全部文件，直接通过文件行复选框调整选择，不提供额外展开按钮或选集弹窗。修改时先停止原传输，保存新选择和容量，再按新清单校验并恢复运行。取消文件保留已有内容；全部取消暂停任务；已暂停任务修改后保持暂停，已完成任务新增未完成文件重新启动。文件间共享分块仍可能产生邻接字节，不代表取消失效。
