## 目的

为 Electron 的原文件和按需兼容输出提供可 seek、可取消、可释放的本地播放会话，并在整部视频完成处理前尽快开始播放。

### 需求: 受限的本地媒体访问

系统 MUST 只通过 loopback 暴露当前应用登记的媒体会话，并 MUST 使用不可猜测的会话凭据阻止任意路径访问。

#### 场景: 播放已登记的原文件

- **GIVEN** Main 已为导入视频创建有效播放会话
- **WHEN** Renderer 使用该会话 URL 请求媒体
- **THEN** 本地媒体服务必须读取会话绑定的原始文件
- **AND** URL 不得包含真实文件系统路径

#### 场景: 请求未知或过期会话

- **GIVEN** 请求携带未知、已释放或不匹配的会话凭据
- **WHEN** 本地媒体服务收到请求
- **THEN** 服务必须拒绝访问
- **AND** 不得尝试把 URL 路径解释成本地文件路径

#### 场景: 非 loopback 客户端访问

- **GIVEN** 请求不是从本机 loopback 到达
- **WHEN** 客户端尝试访问媒体服务
- **THEN** 服务必须拒绝该请求

### 需求: 原文件支持标准 Range 播放

直接播放会话 MUST 支持无 Range 的完整响应和合法单区间 Range 响应，使浏览器能够加载元数据与随机 seek。

#### 场景: 浏览器请求完整媒体

- **GIVEN** 会话绑定的原文件存在且可读
- **WHEN** 请求没有 Range 头
- **THEN** 服务必须返回成功的完整媒体响应
- **AND** 必须提供正确的媒体类型与内容长度

#### 场景: 浏览器请求合法字节区间

- **GIVEN** 请求包含合法的单个字节区间
- **WHEN** 服务读取原文件
- **THEN** 必须返回对应区间、正确内容长度与 Content-Range
- **AND** 必须声明支持字节区间

#### 场景: 浏览器请求非法区间

- **GIVEN** 请求的字节区间超出文件或格式无效
- **WHEN** 服务处理请求
- **THEN** 必须返回范围不可满足响应
- **AND** 不得读取超出文件边界的数据

### 需求: 兼容流可渐进开始播放

需要兼容 HLS 时，系统 SHALL 在首批通过 Producer 验证的媒体片段就绪后立即开始浏览器附着，而不是等待整部视频处理完成；实际播放成功仍以浏览器首帧确认作为边界。

#### 场景: EAC-3 音频转换

- **GIVEN** 视频轨道可复制且音频需要转换
- **WHEN** 用户开始播放
- **THEN** 系统必须保留原视频轨道并产生兼容音频流
- **AND** 播放器应在整部视频完成处理前进入可播放状态

#### 场景: HEVC 转为 H.264

- **GIVEN** 当前设备不能原生硬解目标 HEVC 配置
- **WHEN** 系统启动兼容播放
- **THEN** 输出视频必须为浏览器可播放的 H.264
- **AND** 硬件编码初始化失败时必须自动降级到可用的软件编码器或给出明确失败

### 需求: HLS 资源只在完整且结构有效后发布

系统 MUST 只向播放器发布已经完整写入且通过生产者验证的 HLS 清单、初始化片段和媒体分片，并 SHALL 提供当前 Renderer 可访问的受限跨域响应。编码型输出 MUST 使用闭合 GOP，并使关键帧间隔与分片策略一致。

#### 场景: 分片仍在写入

- **GIVEN** FFmpeg 正在生成新的媒体分片
- **WHEN** 播放器请求该 generation 的资源
- **THEN** 未完成文件不得作为成功响应提供
- **AND** 清单不得引用尚未可完整读取的分片

#### 场景: 编码型 HLS 首个分片完成

- **GIVEN** 当前档位重新编码视频
- **WHEN** Producer Validator 检查首个 generation
- **THEN** init 与首个媒体分片必须可解析且声明预期 H.264/AAC codec、有效时间戳和独立关键帧边界
- **AND** 只有文件存在或清单时长达到阈值不得单独视为 `producer-ready`

#### 场景: HLS 客户端销毁

- **GIVEN** HLS 客户端已附着 HTMLVideoElement
- **WHEN** 用户换片、回退播放源或退出播放器
- **THEN** 客户端、Worker、网络请求和媒体缓冲必须停止并释放
- **AND** 释放动作不得影响新的播放 generation

### 需求: 转码 seek 保持原始时间线

系统 MUST 允许兼容播放跳转，并 SHALL 将跳转后的媒体时间映射为原视频的 currentTime 与 duration。

#### 场景: 从三十分钟位置续播

- **GIVEN** HISTORY 保存的原视频进度为 1800 秒
- **WHEN** 用户从影视库恢复兼容播放
- **THEN** 系统必须从原视频约 1800 秒位置准备兼容流
- **AND** 播放器与历史观察者显示的时间必须继续以原视频时间线计量

#### 场景: 转码期间再次 seek

- **GIVEN** 兼容会话正在生成媒体
- **WHEN** 用户跳转到新的原视频时间
- **THEN** 系统必须停止消费旧位置的输出并准备新位置媒体
- **AND** 旧位置迟到的片段不得混入新的播放时间线

#### 场景: 原视频具有非零起始时间或可变帧率

- **GIVEN** 原视频轨道具有非零 start time、B 帧、可变帧率或关键帧偏差
- **WHEN** 系统从目标位置创建新的 generation
- **THEN** 逻辑时间必须根据实际首个可播放时间戳校准
- **AND** 字幕、弹幕、进度和结束状态不得仅按请求目标与元素时间简单相加

#### 场景: 从中间位置播放到文件末尾

- **GIVEN** 当前 generation 从原视频中间开始
- **WHEN** 兼容流到达原视频末尾
- **THEN** 播放器必须按原视频逻辑 duration 触发 ended
- **AND** 自动下一集和已看判断必须只触发一次

### 需求: 会话所有权与最终释放

每个播放租约 MUST 具有唯一释放路径；换片、退出、窗口关闭、Renderer 异常和应用退出最终都必须停止相关进程并清理临时资源。

#### 场景: 快速从 A 切换到 B

- **GIVEN** A 的兼容会话仍在异步准备
- **WHEN** 用户加载视频 B
- **THEN** A 的迟到结果不得替换 B 的播放源
- **AND** A 创建的进程、会话与临时资源必须最终释放

#### 场景: 重复调用释放

- **GIVEN** 同一播放租约已经被释放
- **WHEN** 清理流程再次请求释放
- **THEN** 操作必须安全完成且不影响其他活跃会话

#### 场景: 应用异常关闭播放窗口

- **GIVEN** FFmpeg 子进程仍在运行
- **WHEN** 播放窗口销毁或应用退出
- **THEN** 系统必须终止该进程
- **AND** 下次启动不得恢复已经失效的临时会话

#### 场景: 系统睡眠后恢复

- **GIVEN** 兼容播放期间设备进入睡眠且进程或分片请求中断
- **WHEN** 系统恢复运行
- **THEN** 播放器必须恢复当前会话或以明确错误结束并允许重试
- **AND** 不得留下无法释放的旧 generation

### 需求: Producer 就绪与浏览器可播放分阶段确认

系统 MUST 区分 `producing`、`producer-ready`、`attaching`、`playable` 和 `failed`。FFmpeg 资源可消费只代表 `producer-ready`；只有 HLS.js/MSE 完成挂载、媒体元数据有效且 Chromium 解码出首帧后才可以进入 `playable`。

#### 场景: Producer 已产出首批资源

- **GIVEN** manifest、init 和首个分片已经通过结构验证
- **WHEN** Renderer 尚未完成 HLS/MSE 挂载
- **THEN** 会话必须保持 `producer-ready` 或 `attaching`
- **AND** 不得更新最近观看或向用户报告播放成功

#### 场景: 浏览器确认首帧

- **GIVEN** HLS.js 已建立 SourceBuffer 并触发 `loadedmetadata`
- **WHEN** video duration 大于 0 且 `requestVideoFrameCallback` 或等价证据确认首个解码帧
- **THEN** 会话必须进入 `playable`
- **AND** 最近观看、播放成功指标和验收才允许通过

### 需求: 优化档位具有启动期限与单次升级

`copy-video-aac` SHALL 具有默认约 8 秒的浏览器首帧期限。期限内未进入 `playable` 时，系统 MUST 取消旧 generation 并单次升级到 `safe-h264-aac-sdr`，不得让用户无界等待或形成档位循环。

#### 场景: 长 GOP 导致视频复制无法及时首帧

- **GIVEN** `copy-video-aac` 已成功启动 FFmpeg
- **AND** 原视频关键帧结构使 HLS/MSE 在期限内无法解码首帧
- **WHEN** 启动期限到达
- **THEN** 系统必须释放该 generation 并启动安全档位
- **AND** 最终错误必须保留优化档位失败原因与安全档位结果

### 需求: 可观察的准备与失败状态

播放器 MUST 区分探测、准备兼容流、转码播放和失败状态，并向用户提供不会假装已经可播放的反馈。

#### 场景: 首片段尚未就绪

- **GIVEN** 播放计划需要转码
- **WHEN** FFmpeg 已启动但尚无可播放输出
- **THEN** 播放器必须保持明确的准备状态
- **AND** 不得把仅有进程启动视为播放成功

#### 场景: FFmpeg 在首片段前退出

- **GIVEN** 兼容播放正在准备
- **WHEN** FFmpeg 在产生可播放输出前失败
- **THEN** 播放器必须结束加载并展示可理解的错误
- **AND** 临时会话必须被释放

#### 场景: 浏览器附着或解码失败

- **GIVEN** Producer 已经通过结构验证
- **WHEN** HLS.js、SourceBuffer、元数据加载或首帧解码失败
- **THEN** 系统必须以 manifest、MSE、metadata 或 decode 阶段标识失败
- **AND** 不得把错误折叠为无原因的黑屏或持续显示 `0:00`
