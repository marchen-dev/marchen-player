## 目的

确保影视库、HISTORY、字幕、截图和播放列表始终使用稳定的原始媒体身份，并将所有临时播放地址与原始逻辑时间线隔离。

### 需求: 临时播放信息禁止持久化

HISTORY 与影视库 MUST 只持久化稳定媒体数据，不得写入 localhost 地址、端口、会话 token、进程标识或临时分片路径。

#### 场景: 兼容会话保存播放进度

- **GIVEN** 当前视频通过临时 localhost URL 播放
- **WHEN** 系统创建或更新 HISTORY
- **THEN** 记录的媒体路径必须仍是原始文件定位信息
- **AND** 数据库中不得出现当前会话 URL 或 token

#### 场景: 应用重启后从影视库续播

- **GIVEN** 上次播放使用了临时转码会话
- **WHEN** 用户重启应用并点击影视库剧集
- **THEN** 系统必须通过 fileHash 找到原始文件定位信息并创建新播放会话
- **AND** 不得尝试复用上次运行的端口或 token

### 需求: 迁移旧 marchen 路径

系统 MUST 将已有 HISTORY 中路径型 `marchen://` 数据迁移为当前平台可用的原始文件定位信息，并在迁移期间保持旧记录可读取。

#### 场景: 迁移 macOS 路径

- **GIVEN** HISTORY.path 为 `marchen:///absolute/video.mkv`
- **WHEN** 数据库升级执行
- **THEN** 记录必须转换为等价的绝对文件路径
- **AND** fileHash、进度、弹幕、字幕和匹配信息必须保持不变

#### 场景: 迁移 Windows 盘符或 UNC 路径

- **GIVEN** HISTORY.path 是旧格式的 Windows 盘符或网络共享 `marchen://` URL
- **WHEN** 数据库升级执行
- **THEN** 系统必须尽可能恢复等价的 Windows 路径
- **AND** 无法无歧义恢复的记录必须保留并在续播时给出文件不可定位提示，不得静默指向其他文件

### 需求: 影视库使用原始逻辑时间线

影视库进度、继续观看、已看状态与续播位置 MUST 使用原视频 duration 和原视频 currentTime，不得使用转码片段的局部时间线。

#### 场景: seek 后转码流从零计时

- **GIVEN** 兼容播放从原视频 1800 秒位置重新生成且媒体元素局部时间为 5 秒
- **WHEN** 系统保存进度
- **THEN** HISTORY.progress 必须约为 1805 秒
- **AND** HISTORY.duration 必须保持原视频完整时长

#### 场景: 判断剧集看完

- **GIVEN** 当前播放使用分片兼容流
- **WHEN** 原视频逻辑进度达到完整 duration 的既定已看阈值
- **THEN** 影视库必须将对应 episode 标记为已看
- **AND** 分片列表当前长度不得改变该判断

### 需求: 实际播放后更新最近观看

作品的最近观看集和最近观看时间 SHOULD 在浏览器实际进入 `playable` 或 `playing` 状态后更新，不应仅因匹配、弹幕、FFmpeg 启动或 Producer 产出首批分片而更新。

#### 场景: 转码准备失败

- **GIVEN** 用户从影视库打开一个需要兼容处理的视频
- **WHEN** FFmpeg、HLS/MSE 挂载或首帧解码在浏览器进入 `playable` 前失败
- **THEN** 该作品不得仅因本次失败被移动到继续观看列表最前
- **AND** 原有观看进度不得被零值覆盖

### 需求: 派生功能使用稳定媒体引用

截图、内嵌字幕、附近字幕与播放列表 MUST 使用原始媒体引用；播放列表当前项 SHOULD 优先按 fileHash 匹配，不能依赖临时播放 URL。

#### 场景: 转码播放时生成影视库缩略图

- **GIVEN** 当前 HTMLVideoElement 加载的是临时兼容流
- **WHEN** 系统在原视频逻辑时间生成缩略图
- **THEN** 截图必须从原始视频取得对应画面
- **AND** 释放临时播放会话不得使已登记的截图任务改读失效 URL

#### 场景: 转码播放时加载内嵌字幕

- **GIVEN** 原 MKV 包含内嵌字幕且播放源为不含字幕的兼容流
- **WHEN** 用户打开字幕列表或选择字幕轨道
- **THEN** 系统必须从原始 MKV 探测并提取字幕
- **AND** 转码会话 seek 或重启不得清空字幕选择

#### 场景: 自动播放下一集

- **GIVEN** 当前剧集使用临时兼容 URL
- **AND** 播放列表包含稳定 fileHash 或原始路径
- **WHEN** 当前原视频逻辑播放结束
- **THEN** 系统必须正确识别下一集并进入统一加载流程
- **AND** 不得因当前 URL 与播放列表 URL 不同而丢失上一集/下一集关系

### 需求: 内部媒体协议下线不影响文件打开

路径型 `marchen://` 在过渡期 MUST 只作为正常直放的临时传输地址，不得作为持久化定位或外部深链；Gateway 直放完成验收并保留可回退路径后，系统 SHALL 下线该内部传输。整个迁移期间 Electron MUST 继续支持文件选择、拖拽、播放列表、历史续播和操作系统文件关联打开。

#### 场景: 第一阶段正常直放

- **GIVEN** 当前媒体可由 Chromium 原生播放
- **AND** Gateway 直放尚未完成验收
- **WHEN** 系统准备播放源
- **THEN** 系统可以继续通过内部 `marchen://` Range 传输
- **AND** HISTORY 与影视库仍必须保存原始路径而非协议 URL

#### 场景: Gateway 直放切换失败

- **GIVEN** 系统正在验证由 Gateway 接管正常直放
- **WHEN** 打包态回归发现 Range、seek、影视库或文件打开异常
- **THEN** 系统必须能够恢复使用已验证的内部直放传输
- **AND** 不得在回退路径失效前删除内部协议实现

#### 场景: 双击关联视频文件

- **GIVEN** 操作系统已将支持的视频扩展名关联到 Marchen
- **WHEN** 用户双击视频文件启动或唤醒应用
- **THEN** 应用必须按原始路径进入统一加载流程
- **AND** 文件打开入口不得把协议 URL 作为持久化定位信息

#### 场景: 没有外部深链需求

- **GIVEN** 产品没有定义可由外部调用的 Marchen 深链命令
- **WHEN** 本变更实施外部协议清理
- **THEN** 系统 MUST 停止注册可由外部调用的 `marchen` 深链协议
- **AND** 该操作不得提前移除过渡期内部 `protocol.handle` 媒体传输
