## 目的

根据原始媒体结构与当前浏览器设备能力选择最小必要的兼容处理，优先保持原始视频画质并避免无意义转码。

### 需求: 分轨道探测媒体兼容性

系统 MUST 分别识别容器、视频轨道、音频轨道和原始时间线，不得仅凭文件扩展名决定播放方式。

#### 场景: MKV 包含 HEVC 与 EAC-3

- **GIVEN** 用户打开一个扩展名为 MKV 的文件
- **WHEN** 系统探测媒体
- **THEN** 结果必须分别描述 MKV 容器、HEVC 视频、EAC-3 音频及原始 duration
- **AND** 任一轨道探测失败不得被误报为另一轨道不兼容

### 需求: 主轨道选择确定且可重复

系统 MUST 在没有音轨切换 UI 时确定性地选择一个主视频轨道和一个主音频轨道，排除封面附件，并遵循默认标记、语言信息和稳定顺序。

#### 场景: 文件包含封面和多条音轨

- **GIVEN** 媒体包含 attached picture、正片视频、默认日语音轨和评论音轨
- **WHEN** 系统生成播放计划
- **THEN** 必须选择正片视频并排除封面附件
- **AND** 必须优先选择默认音轨，不得随机切换到评论音轨

### 需求: 缺失输入事实不得被当作兼容证明

系统 MUST 将 ffprobe 的原始事实与面向目标容器的 codec string 分开建模。缺失 `mime_codec_string`、色彩元数据或目标 fMP4 codec 表达时，系统不得默认认为该轨道可以安全复制到 MSE/HLS 输出。

#### 场景: HEVC 缺少 RFC 6381 codec string

- **GIVEN** ffprobe 已识别输入视频为 HEVC Main10
- **AND** 输入没有提供可直接用于 MediaCapabilities/MSE 的 `mime_codec_string`
- **WHEN** 系统评估复制视频到 fMP4 HLS 的优化档位
- **THEN** 系统必须通过确定性映射或实际目标输出探测补齐目标 codec 事实
- **AND** 无法补齐时不得仅因能力查询被跳过就选择视频复制

### 需求: HEVC 原生硬解优先

系统 MUST 在 HEVC 被当前浏览器报告为支持时优先使用原始视频轨道，不得默认转换为 H.264。`smooth` 是预测性流畅度信息，`powerEfficient` 是功耗倾向信息，二者均不能单独触发视频转码。

#### 场景: 当前设备支持 HEVC 硬件解码

- **GIVEN** 原视频轨道为 HEVC
- **AND** 浏览器能力结果表明该配置受支持且流畅
- **WHEN** 系统生成播放计划
- **THEN** 视频处理必须选择直接播放或复制视频轨道
- **AND** 不得选择视频重新编码

#### 场景: HEVC 能力结果未知

- **GIVEN** 原视频轨道为 HEVC
- **AND** 浏览器无法提供可信的硬件解码能力结论
- **WHEN** 系统生成首次播放计划
- **THEN** 系统 SHOULD 先尝试原生播放
- **AND** 必须保留实际解码失败后的单次兼容回退

#### 场景: HEVC 明确不支持

- **GIVEN** 原视频轨道为 HEVC
- **AND** 当前浏览器明确不支持目标配置
- **WHEN** 系统生成播放计划
- **THEN** 系统必须选择兼容的视频转码计划

#### 场景: HEVC 受支持但预测不流畅

- **GIVEN** 原视频轨道为 HEVC
- **AND** 当前浏览器报告 supported 为 true 且 smooth 为 false
- **WHEN** 系统生成首次播放计划
- **THEN** 系统必须仍优先使用原始视频轨道
- **AND** 实际解码失败后才允许一次兼容回退

#### 场景: 仅 powerEfficient 为 false

- **GIVEN** HEVC 能力结果为 supported 且 smooth
- **AND** powerEfficient 为 false 或 unknown
- **WHEN** 系统生成首次播放计划
- **THEN** 系统必须仍优先尝试原生播放
- **AND** 实际解码失败后才允许一次兼容回退

### 需求: 开发态可强制验证固定转码档位

系统 MUST 提供仅在开发构建生效的显式档位开关，使具备 HEVC 解码能力的开发设备也能确定性验证音频优化、安全视频转码和 HDR 降级链路；生产构建 MUST 忽略该开关。旧的 `VITE_FORCE_VIDEO_TRANSCODE=1` 在迁移期 SHALL 作为 `safe` 的兼容别名。

#### 场景: 开发态强制安全视频转码

- **GIVEN** 应用运行于开发构建
- **AND** `VITE_FORCE_TRANSCODE_PROFILE=safe` 或兼容别名 `VITE_FORCE_VIDEO_TRANSCODE=1`
- **WHEN** 系统生成首次播放计划
- **THEN** 系统必须选择 `safe-h264-aac-sdr`
- **AND** 输出必须确定为 H.264 8-bit 4:2:0 与 AAC-LC，不得继续复制不兼容音频

#### 场景: 开发态强制音频优化档位

- **GIVEN** 应用运行于开发构建
- **AND** `VITE_FORCE_TRANSCODE_PROFILE=audio`
- **WHEN** 系统生成首次播放计划
- **THEN** 系统必须选择 `copy-video-aac`
- **AND** 该档位仍须通过目标 fMP4/MSE 输出验证与启动期限

#### 场景: 开发态强制 HDR 降级档位

- **GIVEN** 应用运行于开发构建
- **AND** `VITE_FORCE_TRANSCODE_PROFILE=hdr-sdr`
- **WHEN** 系统生成首次播放计划
- **THEN** 系统必须选择 `hdr-to-sdr-h264-aac`
- **AND** 输入缺少可解释的 HDR 色彩信息时必须返回明确错误，不得虚构 tone-map 参数

#### 场景: 生产构建设置同名变量

- **GIVEN** 应用运行于生产构建
- **AND** 构建环境包含任一强制转码变量
- **WHEN** 系统生成播放计划
- **THEN** 系统必须忽略该开发测试开关

### 需求: 规划器输出固定且可验证的输出档位

系统 MUST 将媒体规划结果限制为 `native`、`copy-video-aac`、`safe-h264-aac-sdr` 和 `hdr-to-sdr-h264-aac` 四种具有完整输出契约的档位，不得按可选 copy/transcode 字段任意拼装未经验证的组合。

#### 场景: 选择音频优化档位

- **GIVEN** 输入视频可以在目标 fMP4/MSE 链路中复制
- **AND** 主音轨需要兼容处理
- **WHEN** 系统生成兼容计划
- **THEN** 计划必须选择 `copy-video-aac`
- **AND** 必须声明目标视频 codec、AAC-LC 音频、目标容器和启动期限

#### 场景: 优化档位无法及时证明可播放

- **GIVEN** `copy-video-aac` 已开始准备
- **WHEN** 它在既定首帧期限内无法产出并完成浏览器可播放验证
- **THEN** 系统必须终止该 generation 并升级为 `safe-h264-aac-sdr`
- **AND** 同一逻辑媒体不得在两个档位之间循环切换

### 需求: 音频与容器采用最小处理

系统 SHALL 在视频轨道可原生使用时只处理不兼容的音频或容器，不得因为 EAC-3 或容器问题重新编码视频。

#### 场景: HEVC 可硬解但 EAC-3 不兼容

- **GIVEN** HEVC 视频轨道可由浏览器硬件解码
- **AND** EAC-3 音频轨道不可播放
- **WHEN** 系统生成播放计划
- **THEN** 计划必须复制视频轨道并只将音频转换为兼容编码

#### 场景: 轨道兼容但容器不兼容

- **GIVEN** 视频和音频轨道都可原生播放
- **AND** 原容器不能被浏览器直接消费
- **WHEN** 系统生成播放计划
- **THEN** 计划必须只重新封装媒体轨道
- **AND** 不得重新编码视频或音频

#### 场景: 全部原生兼容

- **GIVEN** 容器、视频和音频均可由浏览器直接播放
- **WHEN** 系统生成播放计划
- **THEN** 计划必须为直接播放
- **AND** 不得启动转码任务

### 需求: 音频兼容输出可预测

系统 MUST 为需要转码的主音轨输出浏览器稳定支持的 AAC-LC；首版 SHALL 使用 48 kHz，保留单声道或双声道，超过双声道时下混为立体声。

#### 场景: EAC-3 5.1 音轨需要转换

- **GIVEN** 已选择的主音轨为 EAC-3 5.1 且浏览器不兼容
- **WHEN** 系统生成音频转码计划
- **THEN** 输出必须为 AAC-LC 48 kHz 立体声
- **AND** 视频轨道可兼容时必须继续复制而非重新编码

### 需求: 高位深 SDR 与 HDR 必须分开处理

系统 MUST 识别视频位深、色彩空间、传递函数、色彩原色和 HDR/Dolby Vision 信息。位深大于 8 不等于 HDR；只有明确 HDR10/HLG 等 HDR 事实时才允许进入 tone-map 档位。

#### 场景: 10-bit SDR HEVC 必须转为 H.264

- **GIVEN** 原视频为 Main10 HEVC
- **AND** 色彩事实表明其为 SDR 或不存在 HDR 特征
- **WHEN** 当前环境需要视频兼容转码
- **THEN** 系统必须选择 `safe-h264-aac-sdr` 并输出 8-bit 4:2:0 H.264
- **AND** 不得仅因 10-bit 像素格式添加 HDR tone-map 滤镜

#### 场景: HDR HEVC 必须转为 H.264

- **GIVEN** 原视频具有明确 HDR10 或 HLG 色彩事实
- **AND** 当前环境无法直接播放
- **WHEN** 系统生成视频转码计划
- **THEN** 系统必须选择 `hdr-to-sdr-h264-aac` 并显式 tone-map 为 SDR H.264
- **AND** 所需滤镜或像素格式不可用时必须返回明确的不支持错误

#### 场景: 色彩元数据不足以确认 HDR

- **GIVEN** 视频为高位深但缺少可信的 transfer/primaries/matrix 信息
- **WHEN** 系统需要生成兼容输出
- **THEN** 系统不得猜测 HDR tone-map 参数
- **AND** 应选择不含 tone-map 的安全 SDR 档位或返回色彩事实不足的明确错误

### 需求: 运行时失败只回退一次

系统 MUST 在原生播放发生解码不支持错误时允许一次兼容回退，并 MUST 防止回退循环。

#### 场景: 能力判断误报后实际解码失败

- **GIVEN** 当前媒体按原生计划加载
- **AND** 播放器报告 `decode` 或 `not-supported`
- **WHEN** 当前逻辑视频尚未执行过自动回退
- **THEN** 系统必须生成对应的兼容计划并尝试替换播放源
- **AND** 必须尽量保留原播放位置、暂停状态、音量、倍速、旋转、字幕选择、字幕偏移和弹幕状态

#### 场景: 兼容播放也失败

- **GIVEN** 当前逻辑视频已经执行过自动回退
- **WHEN** 替换后的媒体再次失败
- **THEN** 除 `copy-video-aac` 按既定规则单次升级到安全档位外，系统必须停止自动回退并展示最终错误
- **AND** 不得重新切回原生源形成循环

#### 场景: 非解码错误

- **GIVEN** 原生播放发生文件丢失、权限或网络读取错误
- **WHEN** 播放器报告错误
- **THEN** 系统不得将该错误解释为编码不兼容
- **AND** 不得因此启动 FFmpeg 转码

### 需求: Web 平台保持原生边界

Web 版本 MUST 只使用浏览器原生媒体能力，不得启动本地 FFmpeg 服务或自动上传用户视频。

#### 场景: Web 遇到不兼容 HEVC

- **GIVEN** 用户在 Web 版本打开浏览器不能解码的 HEVC 文件
- **WHEN** 能力判断或实际播放确认不兼容
- **THEN** 播放器必须显示明确的浏览器兼容错误
- **AND** 不得尝试访问 Electron 专属兼容后端
