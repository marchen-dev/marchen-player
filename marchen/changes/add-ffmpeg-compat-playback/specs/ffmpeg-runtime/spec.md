## 目的

为 Electron 提供版本固定、平台匹配且可验证的 FFmpeg/FFprobe 执行能力，并在工具不可用时让应用以明确、可恢复的方式降级。

### 需求: 固定版本与构建可追溯

系统 MUST 为每个支持的平台架构使用明确固定的 FFmpeg/FFprobe 版本，并保留二进制来源、校验值和构建能力信息。

#### 场景: 获取匹配平台的二进制

- **GIVEN** 构建目标是受支持的平台和架构
- **WHEN** 构建流程准备 FFmpeg 资源
- **THEN** 系统必须取得清单中该目标对应的固定版本二进制
- **AND** 二进制内容必须通过清单中的完整性校验

#### 场景: 拒绝不匹配或被修改的二进制

- **GIVEN** 下载资源的架构、版本或校验值与清单不一致
- **WHEN** 构建流程验证 FFmpeg 资源
- **THEN** 构建必须失败并指出不一致的目标
- **AND** 不得继续生成包含未知二进制的安装包

### 需求: 单架构资源分发

macOS x64/arm64 与 Windows x64 的每个 Electron 安装包 SHALL 只包含其目标平台架构需要的 FFmpeg 与 FFprobe，不得同时携带其他目标的二进制。本变更不要求 Linux 产物包含 FFmpeg 兼容能力。

#### 场景: 打包 macOS arm64

- **GIVEN** 当前产物目标为 macOS arm64
- **WHEN** Electron 应用完成打包
- **THEN** 应用资源中必须存在可执行的 macOS arm64 FFmpeg 与 FFprobe
- **AND** 不得包含 macOS x64 或 Windows 的对应二进制

#### 场景: Linux 不进入本次构建矩阵

- **GIVEN** 当前构建目标为 Linux
- **WHEN** 本变更的 FFmpeg 资源准备流程执行
- **THEN** 流程不得把 Linux 视为受支持目标
- **AND** 不得因缺少 Linux FFmpeg 资源影响 macOS 或 Windows 产物

### 需求: 开发与打包环境可执行

系统 MUST 在开发运行和打包应用中定位并执行目标架构的 FFmpeg/FFprobe，调用方不得依赖用户全局安装。

#### 场景: 用户没有全局 FFmpeg

- **GIVEN** 系统 PATH 中不存在 FFmpeg
- **WHEN** Electron 执行媒体探测、截图、字幕或兼容播放
- **THEN** 功能必须使用应用携带的二进制正常工作

### 需求: 运行时能力自检与降级

系统 MUST 验证 FFmpeg/FFprobe 可启动并包含兼容播放必需的能力；验证失败时 SHALL 禁用 FFmpeg 兼容能力，但 MUST 保留浏览器原生可播放媒体的直接播放。

#### 场景: FFmpeg 资源缺失

- **GIVEN** 原视频可由浏览器原生播放
- **AND** 应用携带的 FFmpeg 无法启动
- **WHEN** 用户打开该视频
- **THEN** 系统必须继续直接播放原视频
- **AND** 只将依赖 FFmpeg 的截图、字幕转换或兼容播放标记为不可用

#### 场景: 不兼容媒体需要 FFmpeg 但运行时不可用

- **GIVEN** 浏览器不能播放当前媒体
- **AND** FFmpeg 运行时自检失败
- **WHEN** 系统准备兼容播放
- **THEN** 播放器必须显示可理解的兼容后端不可用错误
- **AND** 不得无限重试或停留在无进展的加载状态

### 需求: 编码器自检与真实输入预检分离

系统 MUST 使用受控的合成媒体源验证编码器能否初始化，并 MUST 将真实文件的解复用、解码、滤镜、映射、封装和时间戳验证作为独立 pipeline preflight。编码器自检不得携带尚未打开的真实输入参数或未创建的进度文件描述符。

#### 场景: 验证硬件编码器初始化

- **GIVEN** 系统准备选择平台硬件 H.264 编码器
- **WHEN** 执行编码器自检
- **THEN** FFmpeg 必须从有限时长的 `lavfi` 合成帧编码到受控输出
- **AND** 结果不得受当前真实文件的容器、滤镜或音轨影响

#### 场景: 验证真实文件转码管线

- **GIVEN** 编码器已通过独立初始化检查
- **WHEN** 系统为当前媒体执行 pipeline preflight
- **THEN** 必须验证实际选流、解码、色彩滤镜、音频处理、目标封装和时间戳
- **AND** 编码器成功不得掩盖真实输入管线失败

#### 场景: 执行器未创建 progress fd

- **GIVEN** 当前 FFmpeg 子进程只用于编码器初始化或其他无需进度的任务
- **WHEN** 执行器启动子进程
- **THEN** 参数中不得包含 `-progress pipe:3`
- **AND** 只有执行器显式创建对应 fd 时才允许传入 progress 参数

### 需求: 受控执行与取消

系统 MUST 将媒体路径和用户数据作为字面参数处理，并 MUST 支持取消正在运行的 FFmpeg/FFprobe 工作及回收其输出资源。

#### 场景: 文件名包含空格和命令字符

- **GIVEN** 视频路径包含空格、引号或 shell 特殊字符
- **WHEN** 系统探测或处理该视频
- **THEN** FFmpeg 必须读取准确的目标文件
- **AND** 路径内容不得被解释为额外命令

#### 场景: 用户在任务执行中换片

- **GIVEN** 当前 FFmpeg 任务仍在运行
- **WHEN** 用户打开另一个视频或退出播放
- **THEN** 旧任务必须进入取消流程
- **AND** 旧进程、文件句柄和临时输出最终必须被释放

### 需求: 不可信媒体输入受限

系统 MUST 将本地媒体视为不可信输入，限制 FFmpeg/FFprobe 可访问的输入协议、交互方式、执行时间和诊断输出规模。

#### 场景: 媒体尝试引用外部资源

- **GIVEN** 本地媒体或容器元数据尝试引用未允许的网络或嵌套协议
- **WHEN** FFmpeg/FFprobe 打开该媒体
- **THEN** 任务必须拒绝未授权协议访问
- **AND** 不得等待终端输入或无限阻塞

#### 场景: 损坏文件导致探测无进展

- **GIVEN** 损坏媒体持续产生诊断输出或无法在合理时间完成探测
- **WHEN** 任务达到对应限制
- **THEN** 系统必须终止任务并返回有界错误
- **AND** 不得让日志、内存或磁盘无上限增长

### 需求: 跨进程错误保留执行阶段

系统 MUST 将 probe、encoder-check、pipeline-preflight、transcode、manifest-validation 等执行阶段与退出码、有界 stderr 尾部一起映射为结构化错误；Renderer MAY 展示简化文案，但诊断信息不得在 IPC 边界被无条件丢失。

#### 场景: 色彩滤镜无法建立转换路径

- **GIVEN** FFmpeg 在真实文件 pipeline preflight 或转码时返回滤镜错误
- **WHEN** Main 向 Renderer 报告失败
- **THEN** 错误必须包含实际阶段、退出码和有界 stderr 摘要
- **AND** 播放器不得只显示通用的“转码失败”而无法区分编码器、滤镜或封装问题

### 需求: 任务资源受控

系统 MUST 对转码、截图、字幕和探测任务实施并发与优先级约束，前台兼容播放 SHALL 优先于派生媒体任务。

#### 场景: 转码播放期间生成缩略图

- **GIVEN** 前台兼容播放正在消耗编码资源
- **WHEN** 系统请求截图、缩略图或字幕转换
- **THEN** 派生任务必须排队、降级或在资源允许时执行
- **AND** 不得无约束地并发启动多个重型 FFmpeg 进程

### 需求: 异常残留可恢复

系统 MUST 限制临时会话占用，并在下次启动时清理已失去所有权的旧会话资源。

#### 场景: 应用被强制终止

- **GIVEN** 上次运行未执行正常退出清理并留下转码分片
- **WHEN** 应用再次启动
- **THEN** 系统必须识别并清理超过保留条件的孤立会话目录
- **AND** 清理不得影响当前运行创建的新会话

#### 场景: 可用磁盘空间不足

- **GIVEN** 缓存目录的剩余空间低于安全阈值
- **WHEN** 用户请求新的兼容转码
- **THEN** 系统必须拒绝或停止继续写入并显示可理解错误
- **AND** 原生可播放媒体仍应保持可用
