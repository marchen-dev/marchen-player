## 目的

统一桌面更新入口和生命周期，确保用户可控且播放进度不丢失。

### 需求: 安装前保存与退出

客户端 MUST 在安装退出前完成播放历史保存确认；超时或失败不得宣称保存成功或直接强退。

#### 场景: 安装前保存与退出验证

- **GIVEN** 用户正在播放并确认更新安装
- **WHEN** 更新器请求退出安装
- **THEN** 保存当前媒体进度并获得确认后再释放资源和退出，成功后重启为目标版本
- **AND** 保存失败或超时则中止/延后本次安装，提示重试；不得重复执行退出或残留播放声音

### 需求: Windows 更新状态

Windows 客户端 SHALL 提供检查、下载、准备、等待安装、安装和错误状态，并区分后台与主动检查。

#### 场景: Windows 更新状态验证

- **GIVEN** 用户打开或重新打开关于页
- **WHEN** 检查、下载、校验或准备状态改变
- **THEN** 界面读取当前状态并继续同步，显示版本、说明和真实进度；100% 下载不等于可安装
- **AND** 后台失败不弹阻塞对话框；主动检查明确反馈；用户确认后安装，不默认退出时安装

### 需求: 幂等操作和重试

客户端 SHALL 合并重复检查和下载请求，并为失败提供重试或手动下载。

#### 场景: 幂等操作和重试验证

- **GIVEN** 检查或下载正在进行
- **WHEN** 用户连续点击或网络失败后重试
- **THEN** 最多一个对应任务，旧请求不得覆盖新状态，失败不留下永久下载中提示
- **AND** 应用退出后再启动仍可重新检查，不依赖失效的界面事件

### 需求: 更新成功判断

客户端 MUST 根据实际运行版本变化展示更新成功，不把安装按钮点击视为成功。

#### 场景: 更新成功判断验证

- **GIVEN** 用户尝试安装或手动覆盖安装
- **WHEN** 应用下次启动
- **THEN** 版本确实升高时才展示该版本更新说明；相同版本不展示成功
- **AND** 不通过访问最新版本说明冒充当前已安装版本说明

### 需求: 安装版本决定渠道

客户端 MUST 每次启动从当前版本确定渠道，不提供渠道切换设置。主动检查与后台检查使用同一规则，只升级不降级。

#### 场景: 渠道收敛

- **GIVEN** Alpha 可以接收 Alpha/Beta/正式版，Beta 可以接收 Beta/正式版，正式版仅接收正式版
- **WHEN** 客户端升级并重启
- **THEN** 按实际运行版本重新确定渠道，升级到正式版后不会收到新 Alpha
- **AND** 同版本、较低版本不提示升级，未知渠道格式不启用更新
