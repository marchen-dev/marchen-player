## 目的

定义应用颜色主题的分层色阶、统一色相与作用域边界，使所有普通界面在浅色和深色下共用同一套颜色来源。

### 需求: 深色主题分层色阶

深色主题 MUST 提供至少四个亮度递增、可以肉眼分辨的表面层级：页面底色、卡片 / 弹层、静音 / 输入、选中 / 悬停。相邻两层之间 SHALL 有清晰可辨的亮度差，层级顺序 MUST 为"底色 < 卡片 < 静音 / 输入 < 选中"。

#### 场景: 卡片与页面底色可区分

- **GIVEN** 应用处于深色主题
- **WHEN** 页面上放置一张带边框的卡片
- **THEN** 卡片底色比页面底色更亮
- **AND** 卡片边框在卡片和页面底色上都可见

#### 场景: 输入层与卡片可区分

- **GIVEN** 应用处于深色主题
- **WHEN** 卡片内放置一个关闭状态的开关或一个输入框
- **THEN** 开关轨道或输入框底色比卡片底色更亮，用户无需借助悬停即可看出控件的轮廓

#### 场景: 深色底色不是纯黑

- **GIVEN** 应用处于深色主题
- **WHEN** 打开首页
- **THEN** 主区域底色为深炭灰，不是纯黑
- **AND** 与侧栏、影视库的深色背景并排时没有明显的突兀跳变

### 需求: 统一冷灰色相

浅色和深色主题中的中性灰 MUST 使用同一个冷灰色相（zinc 系），普通界面中 MUST NOT 同时出现纯灰与冷灰两种灰阶。浅色主题 SHALL 保持现有亮度结构，只调整色相。

#### 场景: 设置面板与首页灰阶一致

- **GIVEN** 应用处于深色主题
- **WHEN** 在首页上打开设置面板
- **THEN** 设置面板、首页入口按钮和面板内控件的灰色属于同一冷灰色相

#### 场景: 浅色主题观感基本不变

- **GIVEN** 应用处于浅色主题
- **WHEN** 对比变更前后的首页、设置、下载、媒体源页面
- **THEN** 各层级明暗关系与变更前一致，仅中性灰略带冷调

### 需求: 色板作用域边界

普通界面（首页、侧栏、设置、媒体源、下载、通用弹窗、toast）MUST 只使用全局颜色 token。仅以下两类界面 MAY 使用独立色板：浮在视频上的播放器界面（不随应用主题变化的半透明材质），以及影视库页面（有意保留的氛围例外）。播放器中挂在根节点之外的弹层 SHALL 基于全局色阶取值，并始终呈现深色。

#### 场景: 调整全局深色取值后普通界面同步变化

- **GIVEN** 维护者只修改全局深色 token 的取值
- **WHEN** 重新查看首页、侧栏、设置、媒体源、下载页面和通用弹窗
- **THEN** 以上界面全部同步变化，不存在仍保留旧颜色的局部区域

#### 场景: 播放器弹层在浅色主题下保持深色

- **GIVEN** 应用处于浅色主题且正在播放视频
- **WHEN** 打开播放器设置面板或播放器内的弹窗、toast
- **THEN** 这些界面仍为深色，文字清晰可读

### 需求: 品牌色单一来源

所有界面中的品牌蓝（主操作、进度、强调、开关打开态）MUST 来自同一个品牌色定义，MUST NOT 在组件或局部色板中另写一份相近的蓝色。

#### 场景: 播放器强调色与应用品牌色一致

- **GIVEN** 应用正在播放视频
- **WHEN** 对比播放器设置面板中的强调色、进度条颜色与应用设置中开关打开态的颜色
- **THEN** 三者来自同一个品牌色定义（深色背景上的文字用色允许使用品牌色的提亮档位）

### 需求: 颜色使用约定可查

仓库的 AI 助手指引文档 MUST 写明颜色使用约定：普通界面只使用语义 token，不使用原始色阶类；底色 token 只表示最底层，凸起和选中使用更亮的层级；需要特殊氛围的模块只在作用域内重写 token 的值，不另起平行命名；并列出播放器材质与影视库两个例外及其边界。

#### 场景: 新模块开发者能找到颜色规则

- **GIVEN** 开发者或 AI 助手准备新增一个页面
- **WHEN** 阅读仓库指引文档的 UI 部分
- **THEN** 可以找到颜色 token 的使用规则与例外边界
