## 背景

播放器已支持文件导入、来源勾选和播放中替换 mergedComments。现有 DanmakuEntry/DB_Danmaku 只有 auto/local，load/rematch 中存在仅保留 local 的筛选，不能把网络来源简单伪装成文件或自动匹配来源。当前渲染时钟不包含来源级偏移，需在合并前处理。

已验证的 youku-danmaku 脚本使用视频信息接口、匿名内存 Cookie 和签名、逐分钟弹幕请求及去重。2026-09-27 用户提供链接完成 46 个分段、16429 条；Python 实测只作为协议探索证据。现有代理 extcomment 对该链接返回空列表，不能作为首版依赖。首版抓取运行在 Electron main，浏览器不直连平台接口。

## 目标与非目标

**目标：** 用小范围 UI 和可扩展适配契约，将用户指定链接的弹幕可靠加入当前视频；保持播放连续、来源可恢复、任务可取消。

**非目标：** Web 链接导入、部署后端、修改弹弹play API、整剧批量、自动识别本地视频对应链接、特效弹幕、自动时间对齐、边抓边显示、持续刷新、字幕或解码调优。

## 决策

### 1. 轻量适配器和平台边界

```text
既有弹幕设置：通用输入 / 来源偏移 / 进度
                ↓
Renderer 链接导入服务：媒体身份、状态、提交
                ↓ 受控 IPC
Main 抓取任务：任务归属、取消、进度和预算
                ↓
适配器注册表 → 首个 YoukuAdapter
                ↓
校验后的统一弹幕 + 来源元数据
                ↓
来源持久化 → 合并选中数据 → 现有弹幕引擎
```

共享契约只包含识别结果、标准弹幕、完成/失败结果、进度和取消标识；Main 的适配器提供识别、规范化、元信息和抓取能力。注册表静态编译，不加载用户脚本，不建插件框架。Renderer 不知道 token、签名或平台分段协议；UI 不包含平台名称开关。首版支持标准 v.youku.com 播放页和有效 vid 参数，不扩展短链或任意网页扫描。

### 2. 主进程协议移植

将既有脚本行为移植成 TypeScript：动态读取标题和时长，初始化匿名 token，按真实时长计算预期分段，串行抓取，按平台弹幕 ID 去重；缺 ID 时用时间、文字、颜色组合去重。原始 ID 保留字符串，避免超出 JS 安全整数；播放器 cid 使用结果内稳定的安全整数映射。

通过统一输出转换为现有 CommentModel，时间单位为秒，模式 1，颜色为播放器已接受的 RGB 表达；不绕行 XML。先校验未知响应结构再解析字段，非法记录跳过并统计，排序前也须验证时间，全部无效和真正空结果均不创建来源。分段结构异常不是空数组。

匿名 Cookie 使用任务内存容器，不使用用户浏览器或 Electron 默认登录 session。初始化 TOKEN_EMPTY 下发 token 可继续；抓取阶段令牌失效、风控或需要验证则停止并提示重试，不自动索取账号 Cookie。CNA 为可选，统计域不可用不得阻塞有效弹幕请求。

网络超时/5xx 每请求最多 3 次，退避可取消；其他业务错误不盲重试。初始集中预算：单请求 20 秒、任务 10 分钟、最多 360 个分钟分段、标准结果最多 10 MiB/100000 条、单次响应读取上限 4 MiB。累计转换前后均检查预算，超限明确停止；这些是防失控上界，实测可收紧，不能以截断数据冒充完整结果。

只从经过验证的平台视频 ID 构造固定 HTTPS 接口 URL；拒绝其他 scheme、用户信息及异常端口，不让 IPC 成为任意 URL 代理。HTTP 重定向关闭或逐跳验证为适配器明确允许的目标。日志不输出 Cookie、token、签名请求 URL、弹幕正文或完整原始响应。

### 3. IPC 任务与媒体会话

新增独立 danmaku IPC 分组以减少与正在修改的 player IPC 冲突，沿用现有类型安全封装。导入请求携带唯一 requestId，Main 将任务绑定 sender；每个 sender 最多一个任务。取消只能操作调用窗口所属任务；进度只发回所属窗口且携带 requestId，取消/销毁后清理监听、定时器、Cookie 和网络读取。先订阅进度再开始请求，结果通过请求完成返回。

Renderer 导入服务不绑定面板组件挂载：收起面板继续任务，再打开可查看状态；取消、退出播放、换源或窗口销毁终止。捕获媒体会话身份及导入代次，不能仅依赖 hash（同视频关闭重开也是新会话）。每个异步边界和提交前核对有效性，迟到响应不能修改另一个会话。

原地 rematch 不必取消抓取，但结果提交需等待播放器回到 ready；此时重新读取最新来源列表，再执行串行来源变更。不要拿抓取开始时的数组覆盖期间新增文件或勾选变化。持久化成功才发布新的弹幕状态；缓存/历史应沿实际适配器统一到事务性写入。取消如与事务重叠，事务内复查代次并回滚；明确“提交已完成”后的取消不能撤销成功来源。

### 4. 链接来源与兼容

引入明确的 type: link 分支，保留 auto/local 字段含义。source 采用 link:<provider>:<videoId> 稳定身份；另存 provider、videoId、canonicalUrl、title、offsetSeconds，content 保留原始时间。跨进程字段与 HISTORY 使用同一权威契约或派生类型，不维护不一致副本。

针对当前视频按 source 去重，开始前检查、提交时再次检查；已存在则提示不重复导入，更新数据不在首版范围。来源显示标题、条数和通用“链接弹幕”标识，UI 不硬编码优酷名称，内部保留 provider 便于扩展与去重。

梳理 load/rematch/retry/cache/history 的所有 auto/local 判断：自动刷新只替换对应 dandanplay 自动来源，保留本地和链接来源、选择状态及偏移。新增字段不改变索引，无需为可选非索引字段盲目升级 Dexie 版本；读取旧记录默认使用原语义，缺少偏移按 0 处理。Web 不开放抓取，但共享来源类型及渲染可容忍已有链接记录。

### 5. 时间偏移与 UI

添加区域为单行“链接输入 + 添加按钮”，不增加其他入口。表单关闭浏览器原生校验：链接为空时禁用添加，识别失败等错误在区域内展示，不出现原生校验气泡；新来源固定以 0 秒偏移导入，不在导入前填写偏移。输入框下方为单一状态区，按任务状态切换：识别与保存阶段只显示文字；分段阶段显示标题、完成段/总段、条数及 Progress 进度条（总数未知时只显示文字）；加载中提供取消；失败使用 Alert 并提供重试；空闲时不占位。

存在链接来源时，同一区域下方显示“链接弹幕偏移”：有两个及以上来源时用 shadcn Select 选择，默认选中刚导入的来源；只有一个来源时直接显示标题。偏移使用“− / 数值输入 / +”步进器和重置按钮，按钮每次调整 0.1 秒，输入框在失焦或回车时生效。数值即时更新，约 300ms 防抖后调用一次来源偏移保存并刷新弹幕，不设单独的保存按钮。步进器先作为链接区域的局部组件。偏移编辑不放入来源 Popover（其宽度与列表结构不适合行内编辑），勾选仍使用既有来源列表。Select、输入与按钮沿用播放器设置的深色样式，焦点环统一为 --player-settings-focus 且无 offset，与字幕、来源控件一致。界面整体使用通用文案；普通鼠标箭头、中文标签、键盘操作和既有面板滚动规则保持一致。

offsetSeconds 限制为 [-3600, 3600]、0.1 秒步进，初始 0。合并时从原始 p 时间计算 time + offsetSeconds；小于零的结果在派生列表中忽略，不覆盖原始数据；跨来源按时间排序后送入引擎。偏移仅影响该来源，渲染时钟与视频进度不变；重复调整、换轨、重开都不累积缩放时间。偏移保存失败回退显示并提示，不报告成功。

任务状态为 idle/loading/committing/success/error/cancelled；进度包含阶段、标题、完成段/总段、当前条数，未知总数时不伪造百分比。失败保留链接便于重试。首版全部成功后提交，暂不增加流式合并、自动更新、自动关闭其他来源等策略。

### 6. 验证与实施边界

受控测试覆盖链接校验、令牌初始化/轮换、签名计算、分段边界、超时退避取消、异常响应、ID 精度、颜色、空数据、跳过无效记录、预算和重定向。IPC 测试验证跨窗口隔离及窗口销毁清理。来源测试覆盖换源迟到、持久化竞态、重匹配保留、重复导入、偏移往返、负时间、旧记录。

Electron 实机在持续播放中导入真实链接；实时数量只以当次报告为准，不固定断言必须 16429。验证不暂停、不重置进度、进度取消、重复提示、调整偏移、勾选、重开恢复；受控慢响应场景验证换源与关窗。Web 验证不显示新入口，文件导入继续工作。运行相关 main/runtime 测试、双端 typecheck、定向 lint 及双端构建。

当前还有 HTTP 直链与字幕按需加载工作；实施前重查 checkout/diff，尽量新建独立模块，公共来源/加载服务修改基于最新内容整合，不覆盖其他工作。此次提案不授权部署、提交或推送。

## 风险与权衡

- 网页接口无稳定承诺，匿名成功不保证未来或全部视频可用；错误要可诊断，适配器可单独维护。
- 完整抓取后添加有等待，但保持已加载来源不受失败影响并降低热更新复杂度。
- 一次序列化大量弹幕会产生 IPC/持久化成本，先采用明确预算并测量，不提前建设通用流式框架。
- 自动关联弹幕可能已包含相同平台内容，首版只保证同链接重复导入去重，不做跨来源模糊文本去重；用户可使用已有勾选控制。
- 片源剪辑差异可能不是单一时间偏移能够修正，本轮不承诺自动同步或分段映射。
