## 目的

提供与播放器媒体时钟同步、在交互和高密度场景下仍能保持可见弹幕互不碰撞的 DOM 弹幕能力。

### 需求: 滚动弹幕安全追击

系统 MUST 根据前后滚动弹幕的可见位置、尺寸、速度和剩余显示时间判断轨道是否安全；后一条弹幕在前一条完全离屏前不得追上或覆盖前一条。

#### 场景: 后一条弹幕速度更快

- **GIVEN** 同一轨道已有一条尚未离屏的滚动弹幕
- **WHEN** 一条速度更快或宽度更大的滚动弹幕到达显示时间
- **THEN** 系统只在两条弹幕全程不会相交时允许其进入该轨道
- **AND** 没有安全轨道时按照高密度策略延后或跳过该弹幕，不得强行重叠显示

#### 场景: 前一条弹幕尚未完整进入画面

- **GIVEN** 同一轨道的上一条滚动弹幕尾部仍位于画面右边界之外
- **WHEN** 新滚动弹幕请求进入轨道
- **THEN** 系统 MUST 拒绝复用该轨道

### 需求: 轨道状态与可见动画同步

系统 MUST 让碰撞状态反映弹幕真实的播放、暂停、恢复、倍速和退出状态；不得只按原始时间推演已经偏离实际动画的轨道位置。

#### 场景: hover 暂停单条弹幕

- **GIVEN** 一条在屏滚动弹幕因 hover 被暂停
- **WHEN** 后续弹幕到达并请求分配轨道
- **THEN** 被暂停弹幕仍被计为可见且占用其轨道
- **AND** 后续弹幕不得穿过或覆盖该弹幕

#### 场景: hover 后恢复

- **GIVEN** 一条滚动弹幕已经暂停一段时间且轨道状态保持占用
- **WHEN** 用户结束 hover 并恢复该弹幕
- **THEN** 系统从恢复后的真实状态继续碰撞判断
- **AND** 恢复过程不得使其与同轨弹幕相交

#### 场景: 播放倍速改变

- **GIVEN** 屏幕上已有多条弹幕且视频正在播放
- **WHEN** 播放倍速在弹幕运动期间改变
- **THEN** 所有可见弹幕和后续轨道判断 MUST 使用一致的新速率
- **AND** 变速前后均不得产生追击重叠

### 需求: 遮挡区域更新保持原子一致

系统 MUST 在播放器控制器显隐、拖动或尺寸变化时同步更新遮挡约束和轨道占用，禁止出现“旧节点仍可见但轨道已被视为空闲”的中间状态。

#### 场景: 拖动悬浮控制器

- **GIVEN** 屏幕上已有弹幕且悬浮控制器正在显示
- **WHEN** 用户连续拖动控制器并多次更新遮挡区域
- **THEN** 现有弹幕的轨道占用 MUST 持续保留或与节点一起原子清除
- **AND** 拖动期间进入的新弹幕不得与仍可见的旧弹幕重叠

#### 场景: 控制器自动隐藏或重新显示

- **GIVEN** 屏幕上存在可见弹幕
- **WHEN** 控制器从显示切换为隐藏或从隐藏切换为显示
- **THEN** 后续弹幕使用最新遮挡区域
- **AND** 轨道状态不得因遮挡区域变化而丢失现有占用信息

### 需求: 多轨高度和跨模式垂直避让

系统 MUST 按弹幕实际可见高度占用一条或多条虚拟轨道，并协调滚动、顶部和底部弹幕的垂直位置，使同时可见的弹幕矩形不相交。

#### 场景: 弹幕高度超过单条轨道

- **GIVEN** 一条弹幕的实际高度超过单条虚拟轨道高度
- **WHEN** 系统为其分配位置
- **THEN** 该弹幕占用所有被其覆盖的连续轨道
- **AND** 其他弹幕在其离屏或消失前不得使用这些轨道

#### 场景: 顶部和底部弹幕同时密集出现

- **GIVEN** 顶部与底部固定弹幕在相近时间内到达
- **WHEN** 两类弹幕从各自方向分配垂直位置
- **THEN** 系统 MUST 保持两类弹幕的占用区域不相交
- **AND** 可用空间耗尽时跳过无法安全放置的弹幕

#### 场景: 固定弹幕与滚动弹幕共享显示区域

- **GIVEN** 固定弹幕和滚动弹幕同时处于可见状态
- **WHEN** 新弹幕请求占用与既有弹幕相交的垂直轨道
- **THEN** 系统 MUST 选择其他安全轨道或执行高密度丢弃策略

### 需求: 弹幕设置连续更新

系统 MUST 在调整弹幕持续时间、字号、显示区域或非布局样式时保留在屏节点，不得通过清屏重新应用设置；核心占用与 DOM 动画必须继续保持一致。

#### 场景: 调整弹幕持续时间

- **GIVEN** 屏幕上已有正在运动的弹幕
- **WHEN** 用户调整弹幕持续时间
- **THEN** 在屏弹幕 MUST 保持当前位置并平滑切换到新速度
- **AND** 核心运动进度、WAAPI 动画和后续轨道判断使用同一新速度，不得产生跳位或追击重叠

#### 场景: 调整字体大小

- **GIVEN** 屏幕上已有按旧字号测量和分配的弹幕
- **WHEN** 用户调整字体大小
- **THEN** 已有弹幕保持原字号和原占用直到自然离屏
- **AND** 后续弹幕使用新字号重新测量并安全分配，不得清除已有节点

#### 场景: 调整显示区域

- **GIVEN** 屏幕上已有位于旧显示区域的弹幕
- **WHEN** 用户调整弹幕显示区域
- **THEN** 已有弹幕保持原位置直到自然离屏
- **AND** 后续弹幕只在新显示区域内分配，并继续避让仍可见的已有弹幕

#### 场景: 调整非布局样式

- **GIVEN** 屏幕上存在可见弹幕
- **WHEN** 用户调整不改变节点矩形的样式
- **THEN** 系统直接更新可见节点及后续弹幕样式
- **AND** 不重建轨道、运动进度或节点

### 需求: 状态重建不得产生陈旧占用

系统 MUST 在 seek、resize 和数据替换时，使可见节点、容量统计与轨道占用在同一个状态边界内重建；常规弹幕设置调整 MUST 使用连续更新语义，不得进入该清屏事务。

#### 场景: 播放器尺寸变化

- **GIVEN** 屏幕上已有弹幕
- **WHEN** 播放器窗口或全屏尺寸发生变化
- **THEN** 系统按新尺寸重新建立合法轨道
- **AND** 不得同时保留旧布局节点与已经清空的旧轨道状态

#### 场景: seek 或弹幕数据热更新

- **GIVEN** 屏幕上已有弹幕
- **WHEN** 用户 seek，或重新匹配、导入、切换弹幕源导致数据替换
- **THEN** 陈旧节点和对应轨道占用 MUST 一并清除
- **AND** 系统从新的媒体时间建立调度窗口，不补发已经越过的弹幕

### 需求: 高密度容量保护

系统 MUST 将所有真实可见节点（包括被 hover 暂停的节点）计入容量上限，并在安全轨道或容量不足时优先保证不重叠和播放器流畅度。

#### 场景: 弹幕密度超过可用轨道

- **GIVEN** 高密度弹幕持续到达且所有安全轨道均被占用
- **WHEN** 新弹幕达到显示时间
- **THEN** 系统按照确定性的策略延后或跳过弹幕
- **AND** 可见节点数不得超过配置上限，也不得通过重叠换取更高显示量

### 需求: 可重复的碰撞验收

系统 SHALL 提供自动化验证，能够在支持的桌面场景中采样可见弹幕矩形并判定不允许的相交，而不是仅依赖节点数量或主观截图。

#### 场景: 高密度综合回归

- **GIVEN** 包含长短文本、滚动/顶部/底部模式和集中时间点的高密度样本
- **WHEN** 样本在正常播放、倍速、hover、控制器拖动和 resize 场景中运行
- **THEN** 自动化检查未发现不允许的可见弹幕矩形相交
- **AND** 节点数、丢弃量和长任务数据均被记录，便于判断正确性与性能取舍
