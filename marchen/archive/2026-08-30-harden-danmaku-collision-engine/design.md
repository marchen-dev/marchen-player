## 背景

`@marchen/danmaku-engine` 当前将时间轴、轨道分配、容量统计和 Renderer 分开：核心按媒体时间收集弹幕，`DanmakuLaneAllocator` 只保存每条滚动轨道最后一条弹幕的 `enteredAt/width/duration`，Renderer 再用 WAAPI 创建实际动画。这一模型在理想匀速条件下能够判断基本追击，但有四个结构性缺口：

1. `setExclusionRect` 通过 `resize` 重置轨道，却不清理仍在运行的节点；控制器拖动会连续触发该路径。
2. hover 只暂停 WAAPI 动画，核心仍按媒体时间推进并释放占用与容量。
3. 固定弹幕分别维护顶部、底部数组，但两组数组映射到同一可见高度，密集时会取得相同 y；滚动弹幕又使用另一套独立占用。
4. 轨道高度和滚动宽度以全局字号/Canvas 估算，没有把节点最终可见尺寸作为分配事实。

旧运行时使用过 `danmu.js`。其 Channel/Bullet 模型提供了实际尺寸、多轨占用、在轨队列、完整进入判断和追击 offset 等可参考经验，但本变更不直接恢复依赖，也不复制其运行时结构。Marchen 仍保持纯 TypeScript 核心、DOM Renderer、媒体时钟和平台无关边界。

## 目标与非目标

**目标：**

- 建立唯一的活动弹幕与轨道占用事实源，使核心状态和 DOM 动画生命周期一致。
- 对滚动弹幕进行全程追击判断，而不只检查新弹幕进入瞬间。
- 让顶部、底部、滚动和多行弹幕共享垂直占用约束，安全优先于显示数量。
- 区分“只更新未来布局约束”和“原子清屏重建”，修复控制器矩形变化导致的轨道失忆。
- 让弹幕持续时间、字号、显示区域和非布局样式在不清屏的前提下连续更新，并保持碰撞模型与 DOM 动画一致。
- 保留媒体时钟、seek、倍速、热更新、节点池、容量上限和高密度丢弃语义。
- 用纯算法测试和真实 DOM 矩形采样共同证明不重叠。

**非目标：**

- 不恢复 xgplayer 或把 `danmu.js` 重新加入运行时依赖。
- 不引入 Canvas/WebGL 弹幕，不改变 DOM 作为默认渲染表面的选择。
- 不修改弹弹play数据协议、弹幕匹配、HISTORY schema 或播放器设置项。
- 不实现高级弹幕、人物遮罩、弹幕点赞或直播实时发送。
- 不扩展手机、平板触控或移动端响应式范围。
- 不承诺在所有 CSS 自定义节点上进行任意形状碰撞；本次以标准矩形包围盒为准。

## 决策

### 1. 用活动占用记录替代“每轨最后一条理想弹幕”

核心维护 `ActiveDanmaku` 注册表，并由统一的垂直轨道表引用。每条记录至少包含：弹幕标识、模式、真实宽高、起始轨道、跨轨数量、进入媒体时间、持续时间、运动进度、暂停状态和生命周期状态。

```text
Timeline items
     │
     ▼
待分配候选 ──测量──▶ DanmakuMetrics(width, height)
     │
     ▼
统一轨道占用表 ◀──── ActiveDanmaku registry
     │                         ▲
     ▼                         │ pause/resume/complete
Placement ───────────────▶ DOM + WAAPI
```

轨道表不再只保存最后一条滚动弹幕，而是能查询与候选弹幕垂直跨度相交的全部活动记录。这样固定弹幕和滚动弹幕也能共享占用事实，避免各模式在相同 y 上互相不可见。

活动记录由核心创建，由 Renderer 在 pause、resume、动画完成或节点取消时显式回报状态。容量上限统计活动注册表，而不是仅按预计过期时间统计；被 hover 暂停的节点继续占用轨道和容量。

### 2. 运动进度以媒体时钟为基准，并显式累计单条暂停时间

正常播放和全局暂停继续跟随 `PlaybackClock`。滚动位置使用“媒体时间经过量减去该弹幕累计的单条暂停量”计算，因此视频倍速变化天然反映在媒体时间推进中；Renderer 同时更新 WAAPI `playbackRate`。

hover 开始时，Renderer 在暂停动画的同一动作中通知核心冻结该弹幕的运动进度；hover 结束时通知核心累计暂停区间后再恢复动画。碰撞预测使用冻结后的实际进度，不允许后续弹幕把暂停节点当作继续匀速移动。

为避免核心与 WAAPI 因事件顺序短暂分裂，pause/resume/complete 命令按标识幂等；Renderer 先更新核心状态，再操作动画。动画被取消或节点释放时必须完成占用释放。

### 3. 对垂直相交候选执行连续时间碰撞判断

滚动弹幕仍采用线性运动，但判定对象从“同一编号轨道的上一条”扩展为“垂直跨度相交的全部活动弹幕”。候选必须同时满足：

- 上一条尾部已经完整进入画面，并保留配置的水平间距；
- 若候选速度更快，两条弹幕的相遇时间不得早于前一条完全离屏；
- 前一条暂停时，该轨道在其恢复并形成安全间距或退出前不可复用；
- 计算使用已同步的运动进度和实际尺寸，并保留小的像素容差抵御浮点与亚像素差异。

没有安全位置时沿用“安全优先”的确定性丢弃策略。本变更不增加等待队列，因为延后弹幕会改变原始时间语义并扩大 seek、热更新和优先级复杂度；未来若需要提升保留率，再独立设计有最大迟到时间的队列。

### 4. 以真实矩形尺寸计算多轨占用

核心的测量契约从单一宽度提升为 `{ width, height }`。Renderer 使用与最终节点相同的字体、字号、字重、行高和文本样式完成隐藏测量，再把结果交给核心；轨道跨度为 `ceil(height / laneHeight)`。

为避免每条弹幕交错读写导致强制布局，Renderer 在每帧把候选节点先写入隐藏测量层，再批量读取矩形，随后统一分配与挂载。测量结果按文本和样式修订缓存；字体加载、字号或相关样式变化会使缓存失效。

不选择每个 tick 对所有在屏节点调用 `getBoundingClientRect()`，因为它会把碰撞正确性建立在持续同步布局之上，密集场景成本不可控。真实尺寸只需在入轨时读取，运动状态通过核心事件模型保持同步。

### 5. 使用统一垂直占用表协调三种模式

顶部固定弹幕从可见区域顶部向下寻找连续安全轨道；底部固定弹幕从可见区域底部向上寻找；两者和滚动弹幕都写入同一占用表。它们可以在空间充足时自然靠近，但不能取得已经被另一模式覆盖的垂直跨度。

固定弹幕在持续时间内保持占用。滚动弹幕只有在候选与现有滚动弹幕满足连续时间安全条件时才可复用相同垂直跨度；与固定弹幕垂直相交时，在固定弹幕消失前不复用该跨度。

控制器遮挡矩形先投影成不可分配的垂直轨道集合。因为标准弹幕横贯或居中显示，本次不把控制器的水平空隙视为可用空间，从而用少量密度换取明确且稳定的避让。

### 6. 分离约束更新与原子重建

引擎提供三类设置更新语义和一类状态重建语义：

- **运动重基准**：持续时间变化先捕获每条活动弹幕的归一化运动进度，再同时更新核心活动记录与 WAAPI timing。节点保持当前位置，新速度从同一进度继续，暂停节点继续保持暂停。
- **未来布局约束**：字号和显示区域变化不修改在屏节点。在屏弹幕保留入轨时的真实尺寸、垂直矩形和字号，后续候选使用新字号测量或在新显示区域内分配。虚拟轨道使用稳定的布局基准，真实高度通过跨轨数量表达，避免全局字号变化重新解释旧轨道。
- **节点样式热更新**：不改变节点矩形的样式直接更新活动节点与后续节点，不修改活动占用或运动进度。
- **原子重建**：seek、数据替换和播放器 resize 生成新的 revision；Renderer 清除对应旧节点，核心清除活动注册表和轨道表，再从新的媒体时间继续调度。字体实际加载导致既有测量失效时仍可使用原子重建，不与用户主动调整字号混用。

```text
持续时间 ──▶ rebaseMotion ──▶ 保留位置并平滑变速

字号 / 显示区域 ──▶ updateFutureLayout ──▶ 旧节点自然离屏

控制器移动 ──▶ updateExclusion ──▶ 保留现有占用

seek / resize / replace
        └────▶ begin reset revision
                    ├─ 清 DOM/动画
                    ├─ 清 active/lanes
                    └─ 从新时间继续
```

同值的遮挡矩形更新需要去重，避免拖动或 ResizeObserver 噪声产生无意义工作。控制器消失时只移除未来排除约束，不回收仍在屏弹幕的占用。

### 7. 建立分层碰撞验证

验证分为三层：

1. **纯算法测试**：表格化覆盖不同宽高、速度、间距、暂停区间、跨轨数量、顶部/底部相遇和无安全轨道；加入固定种子的密集序列，逐时间采样矩形并断言不相交。
2. **Renderer 组件测试**：验证测量批次、pause/resume/complete 回报、revision 原子清理、节点池复用和容量统计，不把 WAAPI mock 的调用次数当作碰撞证明。
3. **桌面验收**：使用高密度样本在 Electron 与 Web 窗口态执行正常播放、倍速、hover、控制器显隐/拖动和 resize；周期采集 `[data-danmaku-node]` 的可见矩形，排除尚未入屏或已离屏节点后检查交集，并记录节点峰值、丢弃计数和 Long Task。

验收不要求原生全屏或 Web DOM 全屏，除非实施阶段用户另行授权操作当前电脑。窗口态必须能够证明同一碰撞与布局契约。

### 8. `danmu.js` 仅作为算法与行为参考

继续保留自研包边界，不引入长期依赖。实现可以参考 `danmu.js` 的多轨占用、完整入屏和追击判断，但应基于 Marchen 的类型、媒体时钟和 Renderer 生命周期重新表达。若实施中需要直接改编其源码片段，必须保留相应 MIT 版权和许可说明，并在代码中标注来源；否则不得声称代码由其派生。

## 风险与权衡

- **密度下降**：跨模式共享垂直占用和确定性丢弃会比当前显示更少弹幕，但能保证不重叠。验收同时记录丢弃率，避免正确性修复造成不可接受的稀疏。
- **测量成本**：真实 DOM 尺寸比 Canvas 估算更可靠，但会增加布局读取。批量写入/读取、缓存和在屏上限用于控制成本；高密度验收必须观察 Long Task。
- **双状态漂移**：核心运动模型与 WAAPI 仍是两个执行面。所有动画生命周期必须走幂等同步命令，并通过逐时间矩形采样发现漂移。
- **控制器覆盖现有弹幕**：拖动控制器可能主动移动到现有弹幕上。本变更保证轨道状态不丢失，并让后续弹幕避让；不强制瞬移或重排已经可见的弹幕，以免产生视觉跳跃。
- **字体变化**：字体尚未加载或 fallback 变化会使旧测量失效。字体 ready 触发原子重建；用户主动调整字号只影响后续弹幕。无法确认字体时使用保守尺寸而不是缩小包围盒。
- **新旧字号短暂共存**：用户调整字号后，在屏弹幕保持旧字号，后续弹幕使用新字号。活动记录必须保留各自入轨时的尺寸和垂直矩形，不能用最新全局字号重新计算旧节点位置。
- **变速双状态漂移**：持续时间变化需要在同一操作中重基准核心进度与 WAAPI timing；任一侧更新失败时保留旧速度，不允许只更新动画或只更新碰撞模型。
- **严格跨模式避让**：滚动与固定弹幕共享轨道会降低极端密度下的展示量。若产品后续希望允许跨模式覆盖，应增加显式策略，而不是重新引入隐式重叠。
- **工作区并行改动**：当前播放器设置侧栏仍有未提交改动。实施应限制在弹幕引擎、Renderer 弹幕层和必要的控制器上报契约，避免覆盖无关 UI 变更。
