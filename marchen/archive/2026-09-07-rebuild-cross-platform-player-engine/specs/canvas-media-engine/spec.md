## 目的

提供双端共用的兼容音视频播放能力，保持有界资源占用和明确的媒体质量边界。

### 需求: 无原生 HEVC 解码能力时的软件播放

系统 SHALL 通过 MediaBunny 自定义解码接口接入固定版本 @suemor/libav-hevc@0.1.1 的 HEVC WASM，MUST 在明确的软件解码路径上验证 HEVC Main/Main 10 本地播放，MUST NOT 以硬件解码成功替代软件解码证据；技术方案不达标时不得静默删除 Web 支持目标。

#### 场景: 强制软件解码样片

- **GIVEN** 声明的目标机器和 HEVC Main 10 样片，原生 HEVC 解码不可用或明确禁用
- **WHEN** 使用兼容引擎播放
- **THEN** 记录实际解码路径、帧率、掉帧、音画偏差、内存及 seek 恢复
- **AND** 无可用解码器时显示明确错误，不无限等待，不转为播放用视频编码

### 需求: 音轨解码、切换与播放时钟

系统 SHALL 支持 E-AC-3/AC-3 与选定范围的音频格式、音轨选择、音量静音和倍速不变调；音视频 MUST 使用一致媒体时间。

#### 场景: E-AC-3 多音轨影片

- **GIVEN** 包含多音轨的可解码影片
- **WHEN** 用户切换音轨、暂停恢复或调整倍速
- **THEN** 旧声音被停止，新音轨从当前媒体时间恢复，字幕和弹幕保持同步
- **AND** 声道映射与设备输出有明确处理，不将解出多声道采样误报为 Atmos 或音频直通

#### 场景: 无音轨或音频暂时欠载

- **GIVEN** 无音轨视频，或播放中音频数据暂时不足
- **WHEN** 推进或恢复播放
- **THEN** 无音轨使用可暂停和倍速调整的时钟；欠载按明确缓冲策略协调音视频
- **AND** 不因墙上时间继续流逝而跳过大段尚未播放的媒体

### 需求: 色彩正确与资源有界

系统 MUST 对 HDR10/HLG 输入提供经验证的 SDR 映射，保留必要的位深与颜色信息直到转换完成；队列和帧资源 MUST 有预算与释放机制。

#### 场景: HDR 样片及长期播放

- **GIVEN** PQ 或 HLG、BT.2020 的 10-bit 样片
- **WHEN** 在 SDR 基线下播放并连续切换文件
- **THEN** 画面按明确转换策略显示，不能仅凭出现画面判定色彩正确
- **AND** 输出帧队列不随影片长度增长，退出后解码和声音停止

#### 场景: 不在保证范围的媒体

- **GIVEN** 需要专用 Dolby Vision 处理或压缩音频直通才能满足预期的媒体
- **WHEN** 打开或选择对应能力
- **THEN** 提示实际输出能力；只有经验证的兼容基础层可以播放，不能宣称完整保留特殊元数据

### 需求: 双端生产环境多线程 HEVC

系统 MUST 在目标 Electron 打包环境和正式 Web 部署中提供可验证的多线程 HEVC 软解。运行模式、配置线程数与回退原因 MUST 可诊断，不得把线程池 Worker 总数当作解码线程数。

#### 场景: 正式环境启用多线程

- **GIVEN** 原生 HEVC 不可用，运行环境满足跨源隔离和线程能力
- **WHEN** 使用 libav.js 播放 Main10 媒体
- **THEN** 加载固定版本线程产物并在 Worker 中解码，确认线程配置及真实输出
- **AND** 双端分别测量含帧传输/渲染/音频的体验，不能以 headless 纯解码短测替代

#### 场景: 缺少隔离或线程初始化失败

- **WHEN** 当前环境无法运行线程版本
- **THEN** 使用经验证的单线程降级并报告实际模式，或给出明确错误；不得无限重启或静默转码
- **AND** 单线程降级成功不算正式部署多线程要求验收通过

### 需求: 解码运行时与内存正确性

系统 MUST 正确处理 Worker 定位、线程函数绑定、内存扩容、过期帧和释放，并使用锁定版本、具备 manifest 与源码来源的发布包；播放器构建不自行编译 libav，必要库修复在独立 libav.js 仓库完成并发布新版本后再更新依赖。

#### 场景: 扩容、连续 seek 与切集

- **WHEN** 解码触发共享内存增长或用户连续 seek/切集
- **THEN** 内存视图及帧所有权保持有效，旧任务不能发布帧，退出后线程和资源被释放
- **AND** 不以增加初始内存替代越界问题修复，不把实验补丁或未验证的帧指针跨线程传递直接上线

### 需求: 支持设备上的 HDR 输出验证

系统 SHALL 在本次验证支持设备上的 Canvas HDR10/HLG 输出并将通过的路径纳入交付；其他设备 MUST 保持经验证的 SDR 映射。

#### 场景: HDR 输出能力变化

- **WHEN** 在目标 HDR 设备播放、切换显示器或恢复 GPU
- **THEN** 实际输出与能力报告一致，保留高精度至色彩处理，字幕弹幕可读，SDR 截图色彩正确
- **AND** 未通过 HDR 验证的路径明确记录，不能仅凭有画面或创建浮点 Canvas 宣称通过

### 需求: 按改动范围验证与集中收尾

开发阶段 SHALL 复用未受改动影响的已有证据，仅执行相关检查与代表样片冒烟；MUST NOT 把未执行的检查标为通过。完整播放、打包和双端部署验证 SHALL 集中在收尾执行，解码器/色彩矩阵及4K压力测试仅在对应改动或异常需要时重跑。可选内存诊断接口及线程池优化不作为播放器接入前提，缺失指标报告不可用，不伪造测量。

#### 场景: 更换发布包或继续业务开发

- **WHEN** 播放器接入固定版本发布包，或修改与解码无关的业务代码
- **THEN** 包迁移进行一次相关接口/样片冒烟；无关业务改动不重复完整解码和色彩矩阵
- **AND** 正式发布仍需对应平台的收尾证据，短测不等价于完整验收


浏览器范围调整：Canvas 仅在具备所需 API 的桌面 Chromium 与 Electron 开放；Safari/Firefox 的 Canvas 设置置灰，旧 Canvas 偏好按原生路径处理，禁止自动选择、自动降级和错误页重试进入 Canvas。无法播放统一使用中文错误界面并提供可展开的诊断详情。
