## 目的

提供桌面 Web 与 Electron 共用的媒体来源、按需读取和稳定身份，隔离文件授权差异。

### 需求: 按需读取且不上传本地影片

系统 MUST 按媒体操作所需读取数据，限制读取缓存；本地影片内容 MUST NOT 为兼容播放上传到远端。

#### 场景: 打开和远距离跳转大文件

- **GIVEN** 用户授权的本地 MP4 或 MKV 大文件
- **WHEN** 打开并跳到影片中部
- **THEN** 系统不等待整文件复制完成，不分配与影片总大小线性增长的读取缓存
- **AND** 能观测读取范围、耗时和缓存占用，取消后过期读取结果不再激活播放

### 需求: 按来源和实际环境表达能力

系统 SHALL 提供音视频轨、语言、时长、尺寸、色彩及可播放性信息；未知能力 MUST 与不支持区分，Web 不得仅因平台身份隐藏已实现的媒体功能。

#### 场景: 容器可读但视频不可解

- **GIVEN** 容器与音视频轨信息可读取，所选视频解码不支持
- **WHEN** 查询或打开媒体
- **THEN** 显示对应解码缺失原因，不将可读容器误报为可播放
- **AND** 缺失或昂贵的元数据不阻塞已具备必要信息的操作

### 需求: 文件重新授权与身份恢复

系统 SHALL 以稳定媒体身份保存进度和轨道偏好，MUST NOT 将临时播放地址作为永久文件身份。

#### 场景: Web 刷新后续播

- **GIVEN** 已保存进度的影片，在刷新后文件访问权不再可用
- **WHEN** 用户继续播放
- **THEN** 请求重新选择或授权文件，确认媒体身份后恢复进度
- **AND** 取消授权不丢失历史、不使用失效临时地址，也不自动上传影片

### 需求: 持久化与播放实现解耦

系统 MUST 提供新模型下的媒体身份、观看历史和影视库，区分 Electron 文件路径与 Web 可恢复文件来源；MUST NOT 持久化临时播放地址或以旧解码器流索引直接恢复新轨道。用户允许旧版本不兼容，不要求迁移旧业务数据、协议路径或转码状态。

#### 场景: 更换内核后重新打开影片

- **WHEN** 用户重新打开同一媒体并使用不同播放内核
- **THEN** 按媒体身份恢复进度，重新核对音轨/字幕选择；缺失轨道使用明确默认值
- **AND** 全局内核偏好沿用设置存储，实际 backend 重新探测，不影响 library、弹幕和监控队列表结构

#### 场景: 清理旧转码持久化逻辑

- **WHEN** 删除旧转码链路
- **THEN** 不创建 HLS/job/cache 数据迁移，不保留旧协议路径恢复分支
- **AND** 新存储从新模型初始化，不主动删除旧 origin 数据或监控队列，不降低已用数据库版本

### 需求: 受控 Electron 资源协议

系统 MUST 使用 protocol.handle 提供固定应用来源和授权媒体租约 URL，MUST NOT 将任意磁盘路径解释为可访问资源或使用 bypassCSP 绕过资源策略。

#### 场景: 原生与 Canvas 读取同一媒体

- **WHEN** 两个内核读取已授权媒体
- **THEN** 通过受控媒体来源按需读取，正确处理普通请求、Range、取消和租约撤销
- **AND** 拒绝旧路径 URL 和未授权资源，不依赖 HLS Gateway

#### 场景: 新生产页面来源启动

- **WHEN** 从固定应用 origin 启动打包版本
- **THEN** 相对资源、Worker/WASM 和新存储正常工作，旧 origin 数据不自动搬迁
- **AND** 明确告知存储重置语义，开发 HMR 来源和生产来源分别验证

### 需求: 本次不启用 CSP

系统 SHALL 保持 bypassCSP=false，本次 MUST NOT 新增 CSP meta 或响应头白名单；文件授权和多线程跨源隔离独立处理。

#### 场景: 远程封面与解码资源加载

- **WHEN** 打开媒体库或启动 WASM 解码
- **THEN** 不由新增 CSP 限制资源，跨源隔离要求通过必要来源配置或受控代理满足
- **AND** 验证封面、字幕和监控功能，不将关闭 CSP 当作共享内存自动可用
