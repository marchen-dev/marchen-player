# 屏蔽判定耗时基准（任务 2.5）

环境：Node 24.21，Linux x64，4 核，vitest node 环境。数据为 5 万条合成弹幕，取 3 次中的最小值。
这是开发机上的 Node 实测，用于判断量级，不代表各用户设备上渲染进程的实际耗时。

- 「判定」：规则变化后重新计算被屏蔽 id 集合的耗时，每次增删规则都会发生。
- 「归一化」：对整组弹幕做转简体与转小写的一次性耗时，只在弹幕数组变化时发生。

| 弹幕文本 | 关键词数 | 正则数 | 命中条数 | 判定   | 归一化 |
| -------- | -------- | ------ | -------- | ------ | ------ |
| 大量重复 | 50       | 0      | 0        | 4 ms   | 26 ms  |
| 大量重复 | 40       | 10     | 0        | 15 ms  | 26 ms  |
| 大量重复 | 0        | 50     | 0        | 122 ms | 26 ms  |
| 大量重复 | 500      | 0      | 0        | 2 ms   | 26 ms  |
| 大量重复 | 501      | 0      | 10000    | 109 ms | 26 ms  |
| 全部不同 | 50       | 0      | 0        | 5 ms   | 240 ms |
| 全部不同 | 40       | 10     | 0        | 19 ms  | 240 ms |
| 全部不同 | 0        | 50     | 0        | 124 ms | 240 ms |
| 全部不同 | 500      | 0      | 0        | 8 ms   | 240 ms |
| 全部不同 | 501      | 0      | 10000    | 114 ms | 240 ms |

## 结论

- 关键词：加入"合并正则预筛"前，500 条关键词的判定为 358～517 ms；加入后未命中场景降到 10 ms 以内，
  20% 弹幕命中时约 110 ms。50 条关键词在 5 ms 左右。
- 正则：50 条正则约 120 ms，与关键词数无关，逐条执行。属于用户操作触发的一次性卡顿，可接受，本次不上 Worker。
- 归一化：文本全部不同的极端情况下约 240 ms，每次换弹幕发生一次；没有任何生效规则时不执行。
- 未覆盖：回溯爆炸的病态正则。弹幕文本短，风险有限，但没有做超时保护。
