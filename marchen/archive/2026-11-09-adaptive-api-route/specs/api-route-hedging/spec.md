## 目的

在自动线路模式下调度每一轮 API 请求：首选线路慢或失败时尽快让另一条线路参与，取先返回的结果，并以稳定口径记录每次尝试，供线路质量分析使用。

### 需求: 慢响应时对冲到另一条线路

自动模式下、且请求允许重放（GET，或匹配接口的 POST）时，系统 SHALL 先只向首选线路发出请求；若超过对冲延迟仍未收到响应，系统 SHALL 向另一条线路并行发出同一请求。对冲延迟为：获取弹幕 2500ms，其他接口 1500ms。每一轮请求 MUST 最多尝试两条线路各一次。

#### 场景: 首选线路及时返回，不对冲

- **GIVEN** 自动模式，首选线路为 Cloudflare
- **WHEN** 发起匹配请求，Cloudflare 在 800ms 时返回成功
- **THEN** 只发出一次网络尝试，结果来自 Cloudflare
- **AND** 本轮记录为未对冲

#### 场景: 首选线路超过对冲延迟，另一条线路先返回

- **GIVEN** 自动模式，首选线路为 Cloudflare
- **WHEN** 发起匹配请求，1500ms 时 Cloudflare 仍未返回
- **THEN** 系统在 1500ms 时向 EdgeOne 发出同一请求
- **AND** EdgeOne 先返回成功时，本轮结果取自 EdgeOne，Cloudflare 的尝试被取消

#### 场景: 对冲后首选线路仍先返回

- **GIVEN** 自动模式，已经对冲到 EdgeOne
- **WHEN** Cloudflare 先于 EdgeOne 返回成功
- **THEN** 本轮结果取自 Cloudflare，EdgeOne 的尝试被取消

#### 场景: 获取弹幕使用更长的对冲延迟

- **GIVEN** 自动模式
- **WHEN** 发起获取弹幕请求，首选线路在 2000ms 时返回
- **THEN** 不发出对冲请求

#### 场景: 不可重放的写请求不对冲

- **GIVEN** 自动模式
- **WHEN** 发起非匹配接口的 POST 或 DELETE 请求，且首选线路响应很慢
- **THEN** 只请求首选线路，不向另一条线路发出请求

### 需求: 首选线路提前失败时立即启用另一条线路

自动模式下，首选线路在对冲延迟之前以可降级的错误失败时（网络错误、超时、HTTP 408 或 5xx），系统 SHALL 立即向另一条线路发出请求，不等待对冲延迟。

#### 场景: 首选线路网络错误立即降级

- **GIVEN** 自动模式，首选线路为 Cloudflare
- **WHEN** Cloudflare 在 300ms 时返回网络错误
- **THEN** 系统立即向 EdgeOne 发出请求
- **AND** EdgeOne 成功时本轮结果取自 EdgeOne

#### 场景: 对冲后其中一条线路失败，等待另一条

- **GIVEN** 已经对冲，两条线路都在请求中
- **WHEN** EdgeOne 返回 502
- **THEN** 本轮继续等待 Cloudflare 的结果，不立即失败

### 需求: 不可降级的结果立即结束本轮

任一线路返回不可降级的结果时，系统 SHALL 以该结果结束本轮并取消仍在进行的另一次尝试。不可降级的结果包括：HTTP 200（含业务层失败）与除 408 之外的 4xx（如签名相关的 401、404）。签名过期的纠偏重试 MUST 仍在单次尝试内完成，不视为切换线路。

#### 场景: 业务失败直接返回

- **GIVEN** 自动模式
- **WHEN** 首选线路返回 HTTP 200 且业务字段表示失败
- **THEN** 本轮把该响应原样交给调用方，不尝试另一条线路

#### 场景: 401 不切换线路

- **GIVEN** 已经对冲，两条线路都在请求中
- **WHEN** 其中一条线路返回 401
- **THEN** 本轮以该 401 失败结束，另一次尝试被取消

### 需求: 两条线路都失败时只失败一次

两条线路都以可降级的错误失败时，系统 SHALL 以最后一个错误结束本轮，调用方只收到一次失败，异常只上报一次。

#### 场景: 两条线路都超时

- **GIVEN** 自动模式，匹配请求已对冲
- **WHEN** 两条线路都达到各自的超时
- **THEN** 本轮以超时失败结束，没有第三次尝试
- **AND** 异常上报一次

### 需求: 单次尝试超时

每次尝试 SHALL 使用按接口区分的超时，与它是首发、对冲还是降级无关：获取弹幕 25 秒，匹配 15 秒，其他接口 10 秒。手动模式下的唯一尝试使用同样的超时。

#### 场景: 慢而有效的弹幕响应不被截断

- **GIVEN** 手动模式 EdgeOne
- **WHEN** 获取弹幕请求在 20 秒时返回成功
- **THEN** 本轮成功

#### 场景: 其他接口 10 秒超时

- **GIVEN** 手动模式 Cloudflare
- **WHEN** 番剧详情请求 10 秒仍未返回
- **THEN** 本次尝试以超时失败

### 需求: 手动模式只请求指定线路

手动模式（Cloudflare 或 EdgeOne）下，系统 SHALL 只请求用户指定的线路，不对冲、不降级。

#### 场景: 手动 Cloudflare 很慢也不对冲

- **GIVEN** 手动模式 Cloudflare
- **WHEN** 匹配请求 5 秒仍未返回
- **THEN** 不向 EdgeOne 发出请求

### 需求: 取消

调用方取消请求时，系统 SHALL 立即取消所有进行中的尝试，本轮结果为已取消，不发出新的尝试，也不上报异常。

#### 场景: 对冲期间用户取消

- **GIVEN** 已经对冲，两条线路都在请求中
- **WHEN** 调用方取消请求
- **THEN** 两次尝试都被取消，本轮结果为已取消
- **AND** 不上报异常，也不改变首选线路

#### 场景: 已取消的请求不发出尝试

- **GIVEN** 调用方的取消信号已经触发
- **WHEN** 发起请求
- **THEN** 不发出任何网络尝试

### 需求: 请求遥测口径

每一轮请求 SHALL 发送且只发送一次 `api_request_completed`。除现有字段外，系统 MUST 记录：本轮是否对冲（`hedged`）；首选线路的来源（`first_route_source`：`learned` / `timezone` / `default` / `manual`）；每次尝试相对本轮开始的发起时刻（`started_at_ms`）与发起原因（`trigger`：`initial` / `hedge` / `failover`）。因另一条线路先返回而被取消的尝试 MUST 记为 `superseded`，不得记为失败或用户取消。

#### 场景: 对冲成功的遥测

- **GIVEN** Cloudflare 慢，1500ms 时对冲到 EdgeOne，EdgeOne 先成功
- **WHEN** 本轮结束
- **THEN** `api_request_completed` 中 `hedged` 为 true、`final_route` 为 edgeone、`attempt_count` 为 2
- **AND** Cloudflare 的尝试结果为 `superseded`，EdgeOne 的尝试 `trigger` 为 `hedge`、`started_at_ms` 约为 1500

#### 场景: 遥测失败不影响请求

- **GIVEN** 遥测上报抛出异常
- **WHEN** 请求完成
- **THEN** 调用方仍正常拿到结果

### 需求: 恢复类异常只在真实失败后上报

系统 SHALL 只在首选线路以可降级错误真实失败、另一条线路随后成功时，上报"已恢复"的运维异常；仅因对冲被另一条线路超过时 MUST NOT 上报异常。

#### 场景: 被对冲超过不上报

- **GIVEN** Cloudflare 慢但没有失败，EdgeOne 对冲后先成功
- **WHEN** 本轮结束
- **THEN** 不上报"已恢复"异常

#### 场景: 真实失败后恢复才上报

- **GIVEN** Cloudflare 返回网络错误后，EdgeOne 降级成功
- **WHEN** 本轮结束
- **THEN** 上报一次"已恢复"运维异常
