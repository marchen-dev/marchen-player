# 匹配与弹幕加载恢复交付报告

已实现等待时直接播放、匹配失败恢复、弹幕失败自动继续播放与无中断重试。按钮位于现有加载步骤说明下方，没有按钮下方说明文案。播放中失败和恢复复用已有右下角 Toast 与弹幕设置，不恢复顶部标题。

## 可观察结果

本轮使用真实 90 秒 MP4 样本与受控匹配/弹幕 API 响应。Web 和 Electron 各 17 项交互检查通过；补充验证 Web 深色页面，以及两端在 10 秒恢复后按时显示 10.5 秒弹幕。结果记录在 assets/*results.json，截图与验收案例关联。

Electron 通过真实 Main/Preload IPC 导入本地文件，使用独立 .tmp/loading-recovery/electron-profile，不触碰日常用户数据。全屏状态由应用窗口状态确认。Web 用 Chrome headless；Electron 使用 CDP attach。当前会话未暴露 Chrome DevTools MCP 工具，使用仓库现有 playwright-core 完成等效连接与截图。没有录像。

浏览器测试使用 Vite 实际加载的服务模块 URL，避免 HMR 时间戳不同造成两个测试服务实例。该测试问题已排除，不计作产品缺陷。

## 实现要点与补充修复

- 使用获准命令过滤与 switchMap 统一失效边界，重复恢复命令在 reloading 被拒绝；匹配失败保留完整视频。
- 每次操作使用独立 AbortController。缓存/历史读写校验有效性，同 hash 写入顺序完成，先保存匹配与弹幕快照再更新缓存；历史保存失败不单独污染旧匹配的缓存。
- 后台番剧封面回填改为仅更新仍属于原匹配的封面/新番字段，避免晚返回数据覆盖新弹幕或播放进度。
- 匹配弹窗用已完成的用户意图区分取消，缓存读取较慢时关闭动画也不会取消播放。
- 连续 Toast 的计时上下文隔离，防止继承上一条通知的焦点/悬停暂停计时。

## 范围与限制

本轮证据证明受控失败/慢请求下的恢复交互及本地视频播放，不证明上游匹配准确率、生产服务可用性或全部媒体格式兼容性。未做发布构建、部署或 Windows 实机验证。工作区已有字幕、匹配提示、控制器及 AGENTS.md 等其他改动，本变更未覆盖这些无关工作，也未提交或推送。

设计范围未扩展到自动后台匹配。直接播放终止当前在线加载；后续用户主动恢复时，不补发过去的弹幕、不自动回到开头。验收页状态由用户决定，本轮未代签核。
