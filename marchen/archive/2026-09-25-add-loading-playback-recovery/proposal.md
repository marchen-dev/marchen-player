## 动机

本地视频播放不应被番剧匹配服务不可用或弹幕请求缓慢阻塞。现有流程只支持无准确匹配时手动跳过，以及首次弹幕获取失败后降级；匹配请求报错缺少恢复操作，播放中重新匹配失败还会使加载状态退出可播放态。

## 变更内容

- 保留正常的先匹配、加载弹幕、再播放流程，避免后台晚接入导致开头弹幕缺失。
- 视频导入完成后，在匹配或弹幕请求等待期间，于现有加载步骤说明下方提供“直接播放”按钮，不增加按钮下方说明文案；导入与读取阶段不显示。
- 点击直接播放即终止本次在线加载，取消或忽略未完成请求；保留已确认匹配信息及已有可用弹幕，不自动接入迟到结果。
- 匹配请求失败提供“直接播放 / 重试匹配 / 手动匹配”；无准确匹配时沿用手动选择弹窗，将“不加载弹幕”改为“直接播放”。
- 首次弹幕加载失败自动继续播放并提供“重试弹幕”；播放中重试只更新匹配和弹幕，不重开视频、不改变进度或暂停状态。
- 重试失败保留原匹配和弹幕，切换视频或取消后拒绝旧请求的迟到结果；正常零条弹幕不作为失败。
- 播放后失败反馈及重试复用当前匹配 Toast 和弹幕设置中的匹配信息区域，不恢复已经移除的顶部标题。

## 能力

### 新增能力

- `loading-playback-recovery`：加载期间直接播放、失败恢复操作、播放期间无中断重试及请求隔离。

### 修改能力

无独立既有规范需要修改；本能力补充现有 player-loading 流程约束。

## 影响范围

- `packages/player-loading`：状态、命令、主加载与重新匹配 pipeline、持久化和取消边界及测试。
- Renderer 加载步骤、手动匹配弹窗、匹配 Toast、弹幕设置，以及相关播放运行时衔接验证。
- 覆盖 Electron 和 Web 桌面端，复用现有 API 和播放器内核，不新增依赖、数据库版本或服务端接口。
- 实现时兼容工作区中 `show-matched-anime-title` 的最新 Toast/设置方案及其他未提交改动。
- 文件读取或解码错误仍走媒体错误处理；本次不做立即播放并后台自动匹配、历史弹幕集中补发或自动回到开头。
