## 目的

为分批依赖升级建立必须通过的验收门槛，使失败能够定位到具体批次。

### 需求: 每批升级独立验证

每个升级批次 MUST 在进入下一批之前完成安装、类型检查、相关测试和适用构建验证。

#### 场景: 一批依赖升级完成

- **GIVEN** 当前批次的版本声明与迁移代码已完成
- **WHEN** 执行该批次验收清单
- **THEN** 所有必需检查 MUST 通过后才能开始下一批
- **AND** 失败 MUST 保留到对应批次中修复，不得累计到最后集中处理

### 需求: 验证 Electron 与 Web 用户路径

最终验收 MUST 覆盖 Electron 和 Web 的实际页面加载与核心用户路径，而不能只依赖静态检查。

#### 场景: 验证双端运行

- **GIVEN** 所有依赖批次均已完成
- **WHEN** 分别运行 Electron 与 Web 版本
- **THEN** 两端可用页面 MUST 正常加载并可导航
- **AND** Electron 端 MUST 完成本地视频导入到进入播放页的路径

### 需求: 验证媒体与字幕回归

最终验收 MUST 使用既定媒体样本检查容器、视频、音频和字幕行为，不得把升级成功误判为新增编解码能力。

#### 场景: 执行媒体矩阵回归

- **GIVEN** 存在覆盖 H.264、HEVC、AAC、EAC-3、ASS 和内嵌字幕的测试样本
- **WHEN** 在升级后的 Electron 中逐项加载样本
- **THEN** 结果 MUST 被记录并与升级前基线比较
- **AND** 本变更不得把原本不支持的格式标记为本次必须新增的能力
