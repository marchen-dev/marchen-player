## 目的

定义 Linux 桌面版运行时与系统交互的可观察行为：外部打开文件、窗口外观与拖拽、平台相关文案以及视频解码策略，使 Linux 用户获得与其他桌面端一致的基本体验。

### 需求: 外部打开文件

Linux 上通过文件管理器、命令行参数或"打开方式"启动视频或 `.torrent` 文件时，应用 SHALL 打开该文件。应用已在运行时再次打开文件，MUST 由已有窗口接收并打开，并把窗口恢复到前台；MUST NOT 启动第二个实例或丢失该文件。

#### 场景: 冷启动打开视频

- **GIVEN** Marchen 未运行
- **WHEN** 用户在文件管理器中用 Marchen 打开一个 MKV 文件
- **THEN** 应用启动并开始加载该视频

#### 场景: 应用已运行时打开另一个视频

- **GIVEN** Marchen 已运行且窗口最小化
- **WHEN** 用户在文件管理器中用 Marchen 打开另一个视频
- **THEN** 已有窗口恢复并显示，开始加载新视频
- **AND** 系统中只有一个 Marchen 实例

### 需求: 窗口外观与可点击区域

Linux 主窗口 SHALL 使用系统原生标题栏完成移动、缩放、最小化、最大化与关闭。窗口内容区顶部 MUST NOT 存在拦截点击的透明拖拽层，页面头部按钮与播放器控件在窗口顶部区域 MUST 可正常点击。

#### 场景: 顶部按钮可点击

- **GIVEN** Linux 上打开设置页或播放器页
- **WHEN** 用户点击内容区顶部 48px 内的按钮
- **THEN** 按钮正常响应，而不是开始拖动窗口

#### 场景: X11 与 Wayland 下均可用

- **GIVEN** 分别在 X11 与 Wayland 会话中运行
- **WHEN** 用户拖动标题栏、双击最大化、进入与退出全屏
- **THEN** 窗口行为正常，全屏退出后布局恢复

### 需求: 平台相关文案

涉及系统文件管理器的界面文案 SHALL 按平台显示：macOS 为"在 Finder 中显示"，Windows 为"在资源管理器中显示"，Linux 为"在文件管理器中显示"。

#### 场景: Linux 历史记录右键菜单

- **GIVEN** Linux 上存在一条本地视频历史记录
- **WHEN** 用户右键该记录
- **THEN** 菜单项显示"在文件管理器中显示"，点击后在系统文件管理器中定位该文件

### 需求: 视频解码策略

Linux 版 SHALL 使用浏览器内核默认的解码配置，MUST NOT 默认强制启用会影响 GPU 进程稳定性的实验性硬件解码或渲染后端开关。当原生解码不支持某视频时，SHALL 回退到兼容内核继续播放，体验与其他平台的回退行为一致。

#### 场景: 原生解码不支持 HEVC

- **GIVEN** Linux 系统无可用的 HEVC 硬件解码
- **WHEN** 用户打开 HEVC 编码的 MKV
- **THEN** 视频通过兼容内核播放，画面、声音、字幕与弹幕正常

#### 场景: 默认配置不导致 GPU 进程崩溃

- **GIVEN** 一个硬件解码驱动不完整的 Linux 环境
- **WHEN** 启动应用并播放 H.264 视频
- **THEN** 应用不因 GPU 进程启动失败而黑屏或崩溃

### 需求: 遥测平台维度

Linux 桌面端的错误与产品事件 SHALL 能与 macOS / Windows 区分（平台与架构），用于评估 Linux 崩溃率与兼容内核回退率；不得为 Linux 引入额外的脱敏或屏蔽。

#### 场景: Linux 崩溃可按平台筛选

- **GIVEN** Linux arm64 客户端发生主进程异常
- **WHEN** 在错误平台中查看该事件
- **THEN** 事件带有 Linux 平台与 arm64 架构信息
