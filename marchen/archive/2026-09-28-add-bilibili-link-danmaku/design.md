## 背景

现有 registry 静态识别优酷；Main task 统一取消、10 分钟超时和窗口归属；Renderer 在 identify 后提前计算来源。B 站 CID 需要异步元信息解析，SS 还需要用户选集。

## 目标与非目标

**目标：** 桌面 BV/分 P、EP 直接导入，SS 明确选集，统一 CID 去重，保持旧流程。

**非目标：** Web 网络获取、登录、短链、历史弹幕、高级/逆向/代码弹幕、视频下载、整季批量。

## 决策

- 新 B 站适配器接收白名单主机和严格路径，只用经过校验的 ID 构造固定 API 地址。元信息走 view 或 pgc season，XML 走 comment 主机；禁重定向、无 Cookie，支持取消与超时、有限重试和响应/条数/结果预算。Node fetch 已解压的响应不重复解压。
- 复用现有 xml2js 解析依赖，禁止 DOCTYPE/ENTITY，解析结果以 unknown 校验；普通模式 1/2/3 归一为 1，4/5 保留，其余跳过。平台弹幕 ID 保留字符串，播放器 ID 映射安全整数。
- importLink 结果扩展为单集结果或 selection。SS 返回有上限的剧集列表，每项带 EP 标准链接；选择后重新走受控任务获取 EP 数据，不信任 Renderer 传入 CID。
- identify 保持同步 URL 识别，无网络。BV/EP 初始身份只是请求定位；成功后以实际 CID 的 LinkIdentity 重新计算来源并再次去重。持久化的 canonicalUrl 保持标准 BV?p 或 EP 地址。
- Renderer 增加 selecting 状态与同会话待选数据。取消、换源使待选失效，关闭面板不取消。SS 不默认选择；选择控件复用现有深色 Select 与播放器 portal。
- B 站界面提示当前弹幕池。不把匿名结果描述为完整历史；XML 与 Protobuf 实测数量不同，首版不自动混合两种结果。

## 风险与权衡

非官方接口可能发生风控或变化；失败明确提示，保留现有来源。SS 多一次选择交互；只支持返回的正片列表，不混入花絮。XML 有容量限制。实测只证明接口可用，须另外检查控制器隔离、构建和 UI。
