## 背景

现有 `AddDanmaku.tsx` 通过隐藏 file input 读取单文件，调用 `local-danmaku.ts` 同步解析和哈希，再通过 `addLocalDanmaku` 保存。组件和服务均要求 ready，无法直接接入 waiting_user。去重在组件内，来源提交由 `mutateDanmaku` 串行化，经 IndexedDB 事务完成后发布新状态。

影视库页面未打开目标视频时不显示本地导入入口，避免写到后台其他视频；本次仅覆盖加载中和播放中的当前视频。

匹配弹窗有两个宿主：加载阶段 `WaitingUserDialog` 与播放阶段 `modules/shared/MatchDanmakuDialog`。前者关闭回调可能取消整个加载；必须区分成功完成、用户关闭和文件选择取消。现有 `playNow` 会先进入 ready，不符合本次“导入失败仍保留弹窗”的要求。

`local-danmaku.ts` 对任一坏条目抛错；10 MB 限制用于保护同步解析，但没有本次大文件性能数据。引擎仅渲染普通滚动、顶部、底部。

## 目标与非目标

**目标：**

- 在两个匹配弹窗场景和原设置入口一致地导入本地文件。
- 本地选择成功保存才进入播放；保留取消、重试、会话隔离与来源去重。
- 取消 10 MB 限制，逐条容错并反馈数量，保持现有持久化格式。
- 获得 Electron / Web 行为与大文件性能证据。

**非目标：**

- Worker、流式解析、拖拽、批量文件导入、新 JSON 格式、高级弹幕渲染。
- 改服务端接口、增加在线匹配请求、调整视频解码或数据库 schema。
- 承诺任意大小文件都能成功导入。

## 决策

### 1. 解析结果与持久化来源分离

解析层返回有效 comments 与 skippedCount，读取层返回 entry 与本次统计；统计仅用于反馈，不加入 HISTORY。移除大小常量、检查及活跃界面的大小文案，更新相关测试，不改历史归档证据。

文件级解析与结构检查仍失败即退出；逐条转换返回有效结果或明确跳过原因，避免用宽泛 catch 吞掉非预期程序错误。XML 只统计根节点下的 d 元素，其他元信息忽略；JSON 顶层保持数组。mode 1/2/3 统一沿用普通滚动语义，4/5 保持底部/顶部，6/7/8/9 和其他模式跳过。每条最多增加一次 skippedCount。

保留现有单位、颜色转换、XML 实体、JSON 默认值与文本内容；不把空白清理、额外格式支持混入此次变更。零有效条目抛可识别的预期校验错误。

### 2. 共享导入协调，UI 只负责呈现

在 Renderer 服务层提取两处共用的文件读取、结果统计及错误分类逻辑；可复用轻量 hook 管理 input、pending 和 Toast。使用开始时捕获的 sessionId、视频身份及操作失效标记，在读取后、提交前后检查。

将按原始文本 MD5 的来源去重放到服务提交边界，并在串行写入内部再次检查；不能仅依赖各组件读取的旧来源快照。保留原有 source 标识格式。读取阶段重复选择受 pending 保护，输入值重置以支持失败后重选。

ready 路径复用事务提交并追加来源，保持视频、匹配信息、进度与其他来源选中状态。更新成功后统一刷新来源查询缓存；不将不完整对象当作完整历史记录写入缓存。

### 3. waiting_user 新增本地完成路径

为 player-loading 增加明确的本地弹幕完成命令或公开方法，接收已解析来源及预期会话，不让纯 TS 包接触 File、DOM、Toast 或遥测 SDK。

```text
waiting_user → 选文件 → 读取/校验 → 保存历史与来源 → ready
     ↑                     │              │
     └──── 取消/校验失败 ───┘              │
     └──────────── 保存失败 ────────────────┘
```

提交期间保留 waiting_user 的候选与搜索 UI，不先调用 playNow。借助现有未匹配记录和历史初始化能力建立合法 HISTORY，携带本地来源；需要时读取并保留已有来源，避免覆盖用户弹幕。最终来源数据通过支持会话校验的持久化事务提交，成功后才发布 ready。不通过需要已有 history 的 cache.commit 直接处理首次导入；实现时扩展 HistoryStore/适配器的受控保存能力，确保初始化与来源提交具有明确失败和取消语义。

保存失败通过本地操作结果返回 UI，仍可在 waiting_user 重试，不切到全页 error。关闭或切换使操作失效，提交前/事务中检查；已提交的原视频历史无需反向删除，但不得污染新视频或发布过期成功结果。

成功采用本地来源，不凭空创建在线作品关联，不继续在线匹配下载；未匹配状态不得误报为在线匹配成功。已有后台任务及迟到结果需受同一会话/操作版本约束，尤其验证优先播放场景中从匹配弹窗导入的行为。

### 4. 弹窗布局与生命周期

标题“选择弹幕”，通过实际 DialogDescription 提供说明和有效的 aria-describedby。搜索框简化为“输入作品名称搜索”。候选区可滚动，底部操作区固定在其外：左侧导入按钮与格式提示，右侧加载阶段的“稍后选择”。使用现有语义 token，桌面小窗口下避免固定高度挤掉底部入口。

处理期间显示“正在导入…”并禁用重复导入、选集及稍后选择等冲突动作；关闭保留现有用户取消语义，并使尚未完成操作失效。文件选择器取消本身不关闭匹配弹窗。成功标记完成后关闭，避免 onClosed 调用 cancel；播放中导入不重载视频。

### 5. 错误与遥测

定义可区分的格式不符、零有效条目、重复来源、会话过期、读取失败、保存失败结果。预期校验拒绝在界面提示，不当异常；非预期读取/保存错误通过 Renderer 现有 reportOperationalError 边界以稳定原因上报。packages 通过结果或 observer 交付信息，不依赖 SDK。

检查现有加载 observer 对新完成路径的事件解释，避免把本地导入记作在线选集成功或“稍后选择”。若需要新增事件或枚举，先更新 contracts 与对应测试，并同步可观测性文档口径。

## 风险与权衡

- 同步 XML DOM 构建、JSON 解析、哈希以及后续合并/排序可能卡顿；本次不预先引入 Worker。以真实样本记录文件字节、条数、设备、解析/哈希/保存及总耗时、主线程长任务和播放响应；无真实大样本时用生成样本补充并明确标注。至少覆盖超过 10 MB 的文件，不能把通过一次等同无限大小支持。
- 解除阈值不会消除内存和存储配额限制；异常需要可恢复提示。严重内存不足可能超出 JS 可恢复范围，不承诺捕获所有进程崩溃。
- 原先会被当作滚动显示的特殊弹幕现在被跳过，属于有意行为变化；统计反馈必须准确。不重写已保存的历史来源。
- waiting_user 首次保存与取消竞态是主要正确性风险；必须覆盖保存失败、读取中切换、事务中取消、重复提交以及重开视频恢复。
- 初次开播与优先播放/重匹配路径不同，需要分别回归，保留在线选集与稍后选择原语义。
