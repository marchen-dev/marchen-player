## 背景

当前 `MatroskaSubtitles.cues()` 的索引路径先等待整轨正文，`resolveEmbeddedSubtitle()` 再收集全部事件并等待字体。`SubtitleCatalogPort.resolve()` 返回完整 URL，`LibassSubtitleAdapter` 以整轨替换为边界。目录与正文分别创建播放资源，虽有租约管理，但并未共享同一个字幕会话。

当前锁定的 libass-wasm JS 与 Worker 提供 createEvent/setEvent/removeEvent，项目封装未暴露；隔离实验已复现 removeEvent 后字幕仍显示、重新追加并回跳画面异常，见 [原始门槛报告](evidence/gate/report.md)。该证据不修改；追加的少量采样通过也不代表整体门槛通过。setEvent 槽位复用尚未验证。兼容 Worker 的字节缓存与 Renderer 独立，Web 原生 video 由浏览器取流；全局缓存不是本次可直接复用的设施。

本变更基于工作区已有 HTTP 直链及字幕恢复改动；实施前确认其实际代码基线，保留其他未提交工作。已有真实来源测量只是问题证据，不作为新实现验收结果。

## 目标与非目标

**目标：** 远程受支持文本字幕先显示目标范围；跳转、偏移、换轨和取消正确；请求与事件有界；把会话编排从 React 中分离，复用字幕会话自身的目录、索引与资源。

**非目标：** 全播放器共享缓存、跨 Worker 读取代理、H5 网络接管、兼容播放队列调优、新内核、依赖 fork/自编译、位图字幕、新增容器或移动端支持。不得将该变更结论推广为所有网络播放卡顿已修复。

## 决策

### 1. 验证门槛先于正式接入

在隔离实验/测试入口中使用锁定依赖验证：空事件轨道加样式初始化、批次追加、重复事件、槽位清空与复用、样式映射、ReadOrder、ASS 动画/定位/重叠、SSA/SRT 映射、暂停与时间偏移、倍速和字号更新。与相同文本完整轨道在相同时间截图对照。验证字体等待时默认字体首批呈现及资源回收。

优先验证固定索引、按需分配且数量有上限的槽位池：createEvent 仅用于分配新槽位，使用公开 setEvent 清空和覆盖已分配槽位，不使用 removeEvent 淘汰。清空后的不可见性、旧字符串处理和重复覆盖的资源行为均须实测，不能由事件数不增长推断内存有界。追加 API 没有稳定业务事件 ID，也没有逐事件确认返回值；Adapter 必须通过有序提交和明确映射管理实例内编号，实验覆盖同一时刻更新、暂停时清空、往返 seek、ReadOrder 和样式变化后的缓存失效及迟到命令隔离。不能在生产代码中直接发送库私有 Worker 消息或每追加一条就 setTrack。若接口不能保持语义或内存无法有界，记录证据并停止后续生产接入，修订本设计；不得临时换库绕过门槛。

### 2. 分层与唯一归属

```text
React Context / 设置 UI：用户操作、订阅状态
                    ↓
SubtitleSession：轨道/窗口/代次/取消/预读/偏好编排
       ↙                                      ↘
SubtitleReader Port                      Libass Adapter
目录、样式、范围事件、覆盖信息             样式映射、事件提交/清理、缩放
       ↓                                      ↓
Matroska Reader + 平台字节源              当前 libass-wasm
```

Session 属于媒体会话，不能绑定易替换的呈现 video DOM 生命周期。它拥有一个平台创建的字幕资源租约，目录与正文复用元数据和索引；释放不撤销播放器的独立资源。Port 返回目录、原始样式、带稳定身份的事件、已验证覆盖区间及降级状态，不返回 UI 文案或 HTTP 细节。

外部字幕导入/历史恢复仍通过现有平台职责处理。完整文本与流式会话采用显式联合类型，完整文本路径保留给本地/外挂；不能靠“url 为空”或 remote 布尔组合猜模式。组件只转发操作和订阅快照；选轨持久化在有效选择成功后进行，延续历史 ID/UID 规则和代次保护，不改数据库。

### 3. 按时间窗口读取，不把 Cues 当完整字幕清单

将索引解析与正文读取分开，索引只解析一次。读取器提供范围查询，事件身份使用轨道 UID 与块位置等稳定信息，不能只按起止时间去重。事件保持原始绝对时间及 ReadOrder。

有效字幕时间沿用当前 `clock + offset` 语义。初始首批优先目标附近小范围，随后补充前瞻窗口；起步参数集中定义为首批后 5 秒、前瞻 30 秒、回看 10 秒、剩余覆盖不足 10 秒补读。参数是待实测调校的内部策略，不是产品性能承诺。暂停最多完成当前有限窗口，倍速按媒体时间消费，不能不断扩大后台范围。目标仍在覆盖内不重新取流。

CueRelativePosition/CueDuration 可能缺失，字幕 Cues 也可能稀疏。参考 https://www.matroska.org/technical/cues.html 。索引用于定位候选 Cluster；只有核验过的范围才报告 complete。必要时检查候选 Cluster 的选中轨道块，不把“找到几个索引项”当覆盖完整。利用可靠持续时间索引补入目标前开始的长事件；无法证明重叠覆盖时进行有限回溯，并返回 partial/unavailable，不能武断以固定回看秒数保证不漏字幕。

缺少字幕索引可借其他轨道 Cluster 索引定位后局部扫描；完全无定位信息时，从已知边界有限扫描。禁止异常后自动改为全片扫描。空但已确认的范围属于 ready；局部可用内容可显示，但 partial 提示不能被隐藏。

### 4. 预算、错误及操作隔离

第一版集中策略：每次目标范围读取含有限回溯最多 16 MiB/128 次底层逻辑 read/15 秒，字幕会话最多 2 个在途读取；元数据与索引另设总计 8 MiB/128 次 read/15 秒预算。预算包括本次失败重试消耗，取消传到传输层。预算不足返回可恢复状态，用户显式重试重建本轮预算，后台不无限循环重试。实现时如果首个 Cluster 前存在大元素，也必须遵守元数据预算。

缓存保留目录/索引和有限事件，不新增通用全局字节缓存。活跃事件和累计分配槽位均不得超过 10000，槽位按需分配，不在启动时预分配上限；原始文本预算 8 MiB；按窗口淘汰但保留仍有效长事件。超预算停止补读并提示，不静默丢掉当前字幕。索引损坏与网络错误分别处理，网络失败不能触发更昂贵扫描。

选轨/跳转/关闭/换源使用 generation + AbortSignal；每个 await 后检查有效性。消费方取消不得释放其他任务资源。共享读取只在本字幕会话内部去重，避免引入跨消费者引用计数框架。目录取消可重试；选择关闭、外挂导入和停止读取优先于自动首选轨道。

状态最小集合为 idle/loading/ready/degraded/error/closed，附带当前覆盖与后台预读信息；已经有可显示内容时后台读取不把 UI 锁回初始加载。

### 5. 渲染边界与字体策略

Adapter 独占 libass API、业务事件 ID 到槽位的映射及空闲槽位列表，对外只接受初始化、事件批次、范围淘汰、缩放和关闭。Session 只决定哪些事件保留，不接触库编号。槽位复用必须完整覆盖时间、时长、ReadOrder、层级、样式、姓名、边距、Effect 和 Text，不能继承旧字段；清空语义经门槛实验确定并验证，不能仅修改 JS 映射。重复业务事件不得分配新槽位，迟到旧代次不得改写已经复用的槽位。槽位满且没有可淘汰事件时按现有预算策略降级，不扩容越界或覆盖仍有效的长事件。

样式和事件保留原始副本；字号更新同时作用于存量及新增事件，沿用现有绝对字号规则。正常预读不 freeTrack，也不自动重建 Worker。换轨、关闭或必须的字号操作保留明确重建边界，并验证无残影与时间错位。

窗口轨道重建仅作为待评估备选：原实验只证明一次重建恢复画面一致，尚未验证切窗闪烁、动画连续性和重解析成本。槽位门槛失败时停止正式接入并修订计划，不自动切换到重建路线，不增加运行时策略开关、依赖补丁或私有 Worker 消息。

字体查询并行且保留 8 秒/32 MiB 约束。首批正文准备好时使用当时已完成的字体结果；尚未完成则取消该轮字体读取并使用内置默认字体，释放迟到结果。本轮轨道不自动迟到换字体，避免重建闪烁。再次显式选轨可以重新尝试；自定义字体精确版式与首句速度的取舍须在验收中展示。

### 6. 验证与交付边界

先使用受控 Range 服务复现高往返延迟并延迟远处正文，确保首批确实独立于整轨结束。逐场景覆盖完整/稀疏/缺失/损坏索引、长事件跨窗、空窗口、首尾连续跳转、并发换轨、字体迟到、暂停、倍速、偏移和字号。记录真实 HTTP 次数与字节，区别于逻辑 read 次数。

Electron 与 Web 桌面各验证受控来源；同一真实来源在相同平台、时间点和冷启动条件下前后至少各 3 次，报告目录就绪、首批目标字幕可用/实际呈现、跳转恢复、请求量与传输量。字体失败不能阻断首批。真实服务跨域不可用时明确未覆盖，不替代为 Electron 通过。

至少连续播放 20 分钟并往返跳转 20 次，检查事件、累计分配槽位、重复覆盖后的 WASM 内存趋势及请求/Worker/Blob 的有界性、关闭后的引用与网络释放；WASM 分配器保留内存不等于泄漏，结合重复循环的增长趋势判断。观察视频实际停顿和呈现，平均解码 FPS 只作辅助，不设无依据的公网秒开承诺。

实施检查包括相关播放器运行时测试、双端类型检查、定向 lint、Electron/Web 构建；仅当实际修改主进程时扩展 main 测试。新增独立证据，不覆盖原变更签核。

## 风险与权衡

- removeEvent 路线已在隔离实验失败；setEvent 的清空、复用、缓存失效和字符串资源释放仍是未知。固定槽位数不能独立证明内存有界；门槛未过只能交付实验结论，不能把后续任务标完成。
- 稀疏/缺失索引无法保证任意远处跳转快速而完整；明确降级比静默扫描更可控，但部分来源的字幕可用性可能受限。
- 放弃迟到内嵌字体可改变排版、字体覆盖或特效观感；默认字体优先需真实样片验收。
- 字幕会话资源复用不等于复用播放器字节缓存；重复媒体读取仍可能存在，后续凭流量证据单独决策。
- 字节缓存不等于解码帧队列，Adapter 一帧槽位不代表 MediaBunny 总缓存；本方案不据此修改视频缓冲。
- 现有完整文本路径应作为明确来源策略保留，禁止随意添加异常回退，避免两套隐式行为长期并存。
