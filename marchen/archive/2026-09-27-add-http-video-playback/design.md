## 背景

当前 `DurableMediaSource` 仅包含 electron-file/web-file，`DurableMediaIdentity.hash` 同时承担历史键和匹配文件 hash 的职责。`openPlaybackResource` 为本地来源创建 Blob URL 或主进程媒体租约，`MediaSourceOwner`、兼容 Worker 和字幕提取共用字节读取抽象。现有 `openRangeSource` 依赖 HEAD、ETag、If-Match 和严格范围响应，适用于受控本地协议，不宜直接放宽为公网通用读取。

HISTORY 以 hash 为主键，持久化校验明确禁止把 HTTP 地址写成 electron-file.path；历史恢复仅支持本地路径与重新选择 Web File。此次新增明确的远程分支，保留原文件分支约束。已归档的加载恢复功能可复用，但远程来源探测失败与弹幕服务失败必须保持不同错误语义。

## 目标与非目标

**目标：**

- 支持 HTTP/HTTPS 文件直链和有限重定向，覆盖桌面 Electron/Web。
- 复用双内核、播放时钟、弹幕、支持的字幕/音轨及截图预览。
- 按需范围读取、取消和有限缓存；不为了探测或 seek 静默整片下载。
- 区分记录标识、内容指纹与临时访问地址，提供核对后的链接替换续播。

**非目标：**

- m3u8/HLS、DASH、直播、网页解析、登录和自定义请求头。
- 新解码内核、转码、远程目录扫描、下载管理、自动续签及服务商集成。
- 全站代理、关闭 Web 安全策略或把 Web 不能访问的来源转发到公网后端。

## 决策

### 1. 显式网络来源与匹配身份分离

新增 `remote-url` 来源，包含持久化的 recordId、用户提交的原始 URL、显示名称、已探测大小及可选内容指纹；不要把 URL 塞入 path。

保持现有数据库 hash 字符串主键不变：本地仍使用原 MD5，远程记录使用带命名空间的 `remote:<uuid>`。这是记录键，永不提交给匹配 API。在加载契约中显式提供真实 `matchHash`/内容指纹，远程缺失时跳过自动识别并提供直接播放/手动匹配。本地旧调用保持兼容。网络打开入口显式携带 recordId（历史恢复/更换链接）或创建新记录，不按签名 URL 或番剧 ID 静默合并不同记录。

内容指纹沿用前 min(16 MiB, size) 字节 MD5 + 完整大小，作为与现有本地历史一致的实用身份核对，不宣称全文件加密级一致性。字段中保留算法说明以便未来升级。无指纹记录可以播放和保存进度，但再次打开或换链接不能无依据套用旧进度，需作为新视频打开。

仅扩展记录的 source 联合和可选字段，不新增索引时无需升级 Dexie schema；实施时确认 DB_History、IPC 可序列化类型及所有 source.kind 分支均覆盖。远程与本地同内容不自动合并来源。

### 2. 统一网络字节来源，保留本地读取实现

```text
打开链接 / 远程历史
        ↓
验证 URL → 有限探测 → 远程 VideoInfo + recordId
        ↓                    ↓
平台读取 Port           可选前缀 hash → 匹配/直接播放
   ├─ Electron 主进程受控网络租约
   └─ Web CORS 范围读取
        ↓
MediaSourceOwner / 原生 URL / 兼容 Worker
        ↓
现有播放时钟、弹幕、字幕、历史
```

增加独立远程 Range 读取模块，输入标准化来源描述、请求生命周期和资源预算，输出 size/read/close 等契约。现有本地 `openRangeSource` 保持严格契约；远程模块负责处理外部服务差异，避免削弱本地授权验证。

探测优先 GET `Range: bytes=0-0`，解析 206 的 Content-Range 得到总长度，不强制 HEAD 成功。后续读取验证状态、范围、总长度及实际字节数，校验无压缩字节表示；遇到 200 立即取消响应体，不调用 arrayBuffer 下载完整文件。HTML、HLS/DASH 清单按响应特征及有限前缀内容拒绝，最终以容器探测确认，不能单凭后缀决定。名称优先合理的 Content-Disposition 文件名，再取 URL 路径，均需安全解码并剥除路径；无法取得名称时使用中性显示名称，提供手动匹配。

优先利用强 ETag，缺失时可用 Last-Modified 辅助判断；有强验证器时使用条件范围读取并处理 412/200，不能将弱 ETag 用作强一致校验。都缺失时允许播放，检查总长度/Content-Range、恢复时重新核对指纹，并明确无法完全检测会话中同大小文件替换。不要把内部租约标识当成上游内容版本。

预算采用现有每源 32 MiB 缓存及单次读取上限；初始网络并发最多 2、每次请求 15 秒超时、瞬时网络/5xx 最多重试 2 次，401/403/404、无效范围及内容变更不自动反复重试。前缀识别总耗时上限 30 秒，失败转为无自动匹配的可播放来源。具体常量集中定义，真实样片验证后若需调整记录理由。原生 video 的浏览器内部缓冲另行观测，不将 JS 缓存预算伪称整个播放器总内存上限。

### 3. Electron 使用主进程网络媒体租约

扩展已有租约注册表和类型化 IPC，区分本地文件与远程来源。主进程仅向已验证的应用窗口创建不可猜测、可撤销、绑定 owner 的租约，Renderer/原生 video/Worker 通过内部媒体协议读取，不直接暴露任意 URL 代理入口。

主进程使用不继承日常登录 Cookie 的读取上下文，不附带 Authorization、用户自定义头或其他应用凭证。支持用户明确提交的 NAS/局域网地址，不将其一概禁止；协议限定 HTTP/HTTPS、拒绝 URL 内嵌用户名密码，每次重定向重验协议，最多 5 跳，不允许转成本地文件或内部应用协议。请求仅用于媒体 GET/探测，不提供任意方法调用。

探测成功后主进程记录本次最终地址、大小和验证器，后续读相同来源并校验变化；用户原始地址用于下次重新打开，不持久化重定向得到的临时签名。主进程将合法上游范围转为内部协议响应；原生 video 的开放式 Range 按固定窗口响应，不建立无限内存缓冲。取消、切源、窗口销毁与页面离开均撤销租约并终止上游读取。

### 4. Web 保持浏览器访问规则

Web 直接使用 CORS 读取远程范围，要求能读取 Content-Range，ETag/Last-Modified/Content-Disposition 等扩展响应头可选；使用这些头时说明相应 expose-headers 要求。条件请求引发的预检必须被服务允许。单范围请求尽量不添加非必要头。

原生 video 设置适当的匿名跨域模式，与媒体探测的无凭证读取一致，使截图可用；兼容 Worker、字幕/缩略图走同一来源策略。保留 COOP/COEP 设置，不通过关闭隔离或 webSecurity 解决问题。

Web 重定向遵守浏览器的有限跳转和 CORS 规则，并受整体超时约束；不能声称能在浏览器中逐跳读取不透明重定向。HTTPS 页面提交纯 HTTP 时提前说明限制；重定向到 HTTP 造成的读取失败也应归类为来源访问失败。fetch 无法准确区分网络/CORS 时显示综合提示，允许用户修改链接或使用桌面版，不输出未经验证的原因。

### 5. 接入既有加载和双内核

在 VideoImporter/加载命令中加入独立的 loadFromUrl 路径，探测得到可播放来源后尝试可选前缀识别，再调用既有匹配/弹幕 pipeline。识别失败后进入有视频上下文的手动选择或可恢复状态，已有直接播放与重试命令保持含义；不发送伪造文件 hash。

网络探测/读取失败属于媒体来源问题，弹幕跳过不能修复不可读取的视频。播放阶段网络错误应携带可重试的来源错误分类，不能一概触发“解码失败 → 切兼容内核”。有限读取重试耗尽后保留时钟/进度快照，通过明确操作重新创建来源并恢复；链接拒绝访问时另提供更换链接入口。

为 MediaSourceOwner、兼容 Worker、音轨切换、内嵌字幕、字体、截图/预览增加 remote 分支，复用 Input/CustomSource 与现有 read Port。Mediabunny UrlSource 可参考其预取机制，但当前需要严格拒绝无 Range 的顺序整片读取，首版不依赖其默认无限重试/无 Range 回退行为。

主播放优先于预览和字幕后台读取，禁止新增全片预扫描。远程播放列表仅包含当前项目；不将 URL 传入本地同目录发现或自动外挂字幕查找。切源代次覆盖导入、hash、元数据、解码 Worker、弹幕和持久化，所有来源 owner 的关闭能取消其读请求。

### 6. 历史与链接替换

PersistentMediaSource 新增远程分支，保存 recordId、原始输入 URL、名称、大小和可选内容指纹。内部 marchen/blob URL 仍不持久化。原始 URL 保存在本机观看记录，用于恢复；普通界面优先显示名称，不在日志、Sentry、PostHog、异常文本或自动截图说明中写查询签名。更换链接窗口按用户操作展示原地址，不自动从剪贴板读取。

历史打开重新探测并核对内容，匹配后才允许进度恢复。更换链接采用“临时候选探测 → 指纹核对 → 提交记录新来源”的顺序；失败/取消不修改旧地址。指纹或大小不同、缺少可比较指纹时不自动继承，提供作为新视频打开或取消。播放过程中记录的新进度不能被较早候选请求覆盖；更新地址、指纹与身份关联需要原子提交。采用同一记录标识，不因签名参数变化重建已核对记录。

### 7. 入口与错误交互

首页原有文件打开入口旁增加次要“打开链接”按钮；复用现有模态栈、输入框和按钮，包含链接输入、打开及取消。校验失败保留输入，提交时防重复，关闭/取消中止探测。遵循中文文案、键盘焦点和默认箭头指针，不增加移动端布局。

使用用户能理解的错误说明：链接无法访问、当前不支持该来源类型、来源不支持按需读取、内容已变化。不要把 Range/ETag 等协议细节作为正常使用流程的必读内容；需要诊断时可在受控详情中显示无敏感数据的错误代码。

## 风险与权衡

- 签名地址有时不允许 HEAD、条件请求或跨域；有限 Range 探测及双端差异需实测，Electron 成功不能代替 Web 验收。
- 前缀 hash + 大小与现有本地识别口径一致，但不是全文件一致性证明；无验证器时会话内变更检测存在限制。
- 原生播放、兼容解码、字幕和预览可能同时读取网络，预算必须覆盖后台任务并可取消，不能只限制单个 fetch。
- 不能支持 Range 的服务器在本版会被拒绝，这是为避免隐藏的大流量下载所作的明确取舍。
- 原始签名链接为恢复需要在本机保存；远程来源数据进入诊断链路时必须统一脱敏，不能仅处理一条错误提示。
- 远程联合类型影响本地路径假设较多，实施时逐个检查 exhaustiveness；保持原数据库记录、文件导入和租约测试。

验证使用可控 HTTP 服务器覆盖范围响应、HEAD 405、无 ETag、重定向、签名过期、超时、CORS 和内容替换；使用支持的原生及兼容样片在桌面 Electron/Web 观察首帧、seek、字幕、弹幕和恢复。受控样片结果不推广为所有网盘、编码或公网服务兼容性结论。
