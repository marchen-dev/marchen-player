## 动机

用户希望直接打开 NAS、文件服务或下载服务提供的视频直链，无需先下载到本地。当前媒体来源仅支持 Electron 文件路径与 Web File，虽然已有双内核和范围读取能力，外部网络地址尚未接入导入、播放、弹幕及历史恢复流程。

## 变更内容

- 首页新增“打开链接”，接受 HTTP/HTTPS 视频文件直链，包括返回视频文件的重定向地址，不要求 URL 必须带视频扩展名。
- 按需读取远端文件，复用原生/兼容双内核及现有播放控制、内嵌字幕和弹幕能力，实际解码支持仍以媒体探测与现有内核为准。
- 第一版要求来源支持有效 Range 和可确定文件长度。无 Range、未知长度或返回网页/播放清单时明确失败，不静默整片下载。
- Electron 使用主进程受控网络读取和媒体租约；Web 直接读取允许 CORS 的来源，明确处理 HTTPS 页面无法访问纯 HTTP 来源的限制。
- 能取得匹配所需数据时，用文件前 16 MiB 的 MD5、完整大小和名称自动匹配。匹配数据不足或请求失败时仍可直接播放、手动匹配及重试。
- 保存远程来源、进度、匹配与偏好。链接失效后支持更换地址；验证为同一内容才沿用原记录，避免将另一视频的进度套入。
- 处理网络中断、取消、跳转进度、切换视频和过期响应；控制预读与缓存，不在日志或遥测中暴露完整签名 URL。

## 能力

### 新增能力

- `http-video-playback`：直链输入、双端网络媒体读取与播放、错误恢复及弹幕接入。
- `remote-video-history`：远程视频身份、观看记录、失效链接更换与续播。

### 修改能力

无独立既有规范迁移；沿用已归档 `add-loading-playback-recovery` 的直接播放和无中断弹幕恢复行为。

## 影响范围

涉及 shared 媒体来源、player-loading 导入/身份、Electron IPC 与媒体协议、Renderer 媒体 owner/Worker/字幕/截图、首页入口及历史恢复。保持现有文件导入和安全路径校验，不把 URL 伪装成文件路径。

仅覆盖桌面 Electron/Web。不支持 m3u8/HLS、DASH、直播、网站页面解析、登录流程、自定义 Cookie/Header、远程目录扫描、离线下载或自动刷新服务商签名。不新增通用公网代理服务，不修改播放器解码架构。
